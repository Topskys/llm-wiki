# RAG知识库权限隔离·素材摘要

## 核心结论

- **核心原则**：权限拦截放在数据层，不依赖大模型 Prompt 约束。
- **反面方案**：Prompt 限制存在提示词注入、幻觉、暴露面失控三大缺陷。
- **全链路五层管控**：入库绑权限 → 检索前置过滤 → 上下文最小化 → 缓存隔离 → 越权审计。
- **分层权限**：租户隔离、角色/部门、用户白名单三层粒度。

## 要点索引

### 一、Prompt 限制为何不足
提示词注入可覆盖约束、幻觉致无视约束、敏感 Chunk 进上下文即暴露。

### 二、全链路权限隔离架构
文档入库绑定权限元数据（Chunk 继承）→ 检索前置过滤（向量引擎层标量过滤）→ 上下文最小化（二次校验+只给必要片段）→ 缓存隔离（Key 绑定用户身份+权限）→ 审计与越权监控（全量日志+告警）。

### 三、检索漏斗坍塌
先召回再过滤的反模式：无权限高相似文档抢占 TopK，有权限内容被挤出，召回质量下降。

### 四、分层权限模型
租户隔离（tenant_id + 命名空间双重隔离）、角色/部门（dept_id + roles）、用户白名单（user_id）。

### 五、向量库 metadata 过滤能力
Pinecone/Qdrant/Weaviate/Milvus/ChromaDB/pgvector/LanceDB 原生支持；FAISS 不支持需降级。

### 六、段落/字段级权限细化
元数据增加 section_id/field_name 维度，同文档内差异化权限。

### 七、权限变更传播
事件驱动：权限中心发变更事件 → 批量更新向量库 metadata + 失效相关缓存。

### 八、性能基准
pre-filter 延迟增加 <10%，post-filter 召回率下降 15%-30%。
