# Loop到Graph演进·素材摘要

## 核心结论

- **核心命题**：单体 Loop 解决"让模型自己做事"，Graph 解决"让系统可靠地把事做完"的生产级问题。
- **演进逻辑**：Graph 不是凭空出现，而是建立在 Prompt → Context → Tool → Loop 四层能力之上；也不是回到死板的传统工作流，而是「结构化骨架 + 节点内部自主」的融合形态。
- **决策口径**：先看任务长什么样再决定结构；三问（分支并行 / 跨会话状态 / 治理要求）都不需要就继续用 Loop，不要过度设计。

## 要点索引

### 一、控制流五层演进（P2）
L1 提示词（说清楚）→ L2 上下文（有依据）→ L3 工具（能动手）→ L4 Loop（会自己干）→ L5 Graph（组织协同干好还可控）。

### 二、单体 Loop 的能力边界（P3–P7）
- **核心价值**：把驾驶权交给模型，人从手把手指挥变为提目标、设边界、验收结果。
- **五大瓶颈**：上下文稀释 / 错误级联 / 工具过载 / 控制太粗 / 定位困难。
- **失控机制**：上下文、错误和工具相互放大（噪 → 偏 → 选），各配 Graph 对策。
- **生产四能力**：停（暂停）、人（审批）、回（恢复）、审（审计），Loop 天然不支持。
- **目标偏移**：古德哈特定律，标（只优化关闭率）→ 捷（寻找指标捷径）→ 失（真实留存下降）。

### 三、Graph 架构本质（P8–P10）
- 概念澄清：不是知识图谱、不是静态流程图，是可执行协作网络，做到可观测·可恢复·可扩展。
- 四要素公式：$G = V \cdot E \cdot S \cdot P$（节点 / 边 / 状态 / 策略）。
- 三种拓扑：扇出与扇入（并）、主管模式（管）、流水线（线）。

### 四、Loop vs Graph（P19–P26）
- **方案案例**：方案A 单 Loop 自审的四缺点 vs 方案B 研究员→写作者→审稿人微型 Graph 三收益。
- **对比维度**：上下文、验证方式、执行效率、失败恢复、开发成本、生产治理。
- **成本三数字**：+90.2% 表现提升、约15× Token 消耗、约80% 性能方差由 Token 用量解释。
- **四笔账**：值（结果价值）/ 钱（运行成本）/ 时（时间成本）/ 维（维护成本）。
- **架构融合**：传统工作流（流）→ ReAct/Loop（环）→ Graph（图）。

### 五、生产落地（P11–P18、P27–P29）
- **七条原则**：架构选型、实施路径、独立验证、确定性边界、权限治理、共享状态协作、状态持久化。
- **可靠性三原则**：规（规则代码化）、验（验证独立化）、态（状态可恢复）。
- **评价三原则**：测（测试真的通过）、标（业务指标真的改善）、人（用户真的受益），配四类任务的现实锚点。

### 六、核心结论（P30）
**能简则简、稳靠确定性、只看真实反馈。**
