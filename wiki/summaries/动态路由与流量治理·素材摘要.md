# 动态路由与流量治理·素材摘要

## 素材信息
- 标题：面向大模型服务的动态路由与流量治理架构研究
- 位置：[[raw/papers/面向大模型服务的动态路由与流量治理架构研究.md]]（已按论文格式规范修订，含 Mermaid 状态机图）
- 性质：工程方案论文（技术方案+防御性设计，非严格同行评审）；侧重架构设计与容错策略

## 核心要点索引

### 问题定义
- 上游 LLM API 有 RPM（并发请求数）与 TPM（Token 消耗配额）双配额，超限返回 429；传统静态路由+简单重试会引发惊群效应导致上游雪崩。
- 现有网关三短板：双配额建模粗糙、SSE 容错简陋、异构降级无能力校验。

### 架构
- 双层：Nginx 边缘网关（负载均衡/安全/粗粒度并发）+ AI 业务网关（鉴权/令牌桶/熔断/动态路由）。→ 详见 [[双层网关架构]]
- MCP 落地：AI 业务网关以 MCP 网关形态呈现——MCP服务端（JSON-RPC）→ MCP路由模块（RAG/Tool/Memory 能力编排）→ LLM调用子模块（令牌桶-熔断-路由降级）。→ [[MCP网关]]

### 关键算法
- **配额**：两级令牌桶（本地快速预拦 + Redis 全局权威），预扣预估 Token + 按请求 ID 退款。→ [[RPM与TPM联合令牌桶]]
- **容错通道分离**：5xx 驱动熔断器三态（Closed/Open/Half-Open + 冷却探测）；429 走配额感知切换（细分 RPM/TPM/月度三类，月度用尽长期失效）。→ [[熔断器状态机]] [[429流量治理]]
- **降级**：同模型换 Key → 能力标签硬/软约束筛选异构降级 → 退避重试；allow_fallback 防 Agent 工具场景误降级。→ [[能力标签驱动降级]]
- **恢复**：半开连续成功 → 灰度回切（渐进放量观测 429/错误率）。→ [[灰度回切]]
- **边界**：已流式 SSE 中断不重试、非幂等禁重试、长上下文低重试、全请求级重试预算。→ [[SSE流式容错]] [[重试预算与幂等保护]]

### 可观测
- 限流/熔断指标（本地/Redis/上游 429 分型、熔断器状态时段）与调度指标（切换成功率、降级频率、回切比例、预算触顶）分层埋点；5 分钟 429 突增或 Key 连拒自动告警下线。
- 双通道独立统计可区分「服务端故障 vs 配额耗尽」，指导扩容或加购。

### 局限与未来（素材原文）
- 局限：能力标签靠人工维护；Redis 引入少量延迟；降级策略为预定义规则无自学习；灰度比例人工调参。
- 未来：TPM 预估模型（语义+Token 预测）、强化学习自适应降级候选、灰度在线实验自动调参。
