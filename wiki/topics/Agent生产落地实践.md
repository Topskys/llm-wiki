# Agent生产落地实践

## 渐进实施路径图

```mermaid
flowchart LR
    A["① 一次调用<br/>能单次解决就不加循环"] --> B["② 单体Loop<br/>需要自主尝试、反复修正时引入"]
    B --> C["③ 微型Graph<br/>先拆最有价值的节点，小步快跑"]
    C --> D["④ 多智能体<br/>业务价值足够、验证收益后扩展"]
```

## 核心结论

- 生产落地的主线：**先看任务选结构 → 沿渐进路径小步走 → 按七条原则做设计 → 用可靠性三原则自检 → 只认真实反馈做评价**。
- 核心原则两条：**先证明需要，再增加节点**；**先看任务长什么样，再决定使用什么结构**。
- 稳定性从来不是靠堆节点数量堆出来的，而是来自**确定性设计**。

## 七条实践原则

### 1. 架构选型：根据任务特征选结构

> **先看任务长什么样，再决定使用什么结构。**

| 任务特征 | 适合方式 | 主要作用 |
|----------|----------|----------|
| 边界清晰、步骤固定 | 提示链 | 按照预设顺序稳定执行 |
| 输入类型差异明显 | 路由 | 先分类，再分发给专职节点 |
| 子任务能够解耦 | 并行化 | 扩大搜索和验证范围 |
| 任务路线无法预测 | 主管—工作者 | 运行时动态规划和调度 |
| 存在明确质量标准 | 评估—优化 | 根据独立反馈反复改进 |

### 2. 实施路径：渐进式演进，不要一步到位

不要一开始就设计十几个Agent，迭代顺序见上图：

1. **一次调用**：能单次解决就不加循环，最简单的方案最可靠
2. **单体 Loop**：需要自主尝试、反复修正时，再引入循环
3. **微型 Graph**：先拆分最有价值的节点（比如把生产和验证拆开），小步快跑
4. **多智能体**：业务价值足够、验证收益后，再逐步扩展节点

> **核心原则：先证明需要，再增加节点。**

### 3. 独立验证：职责分离，不要自写自审

> **别让一个节点既写答案，又批卷子。** 详见 [[独立验证机制]]。

### 4. 确定性边界：模型负责判断，代码负责收口

模型的长处是模糊判断，代码的长处是精确执行，两者要划清边界：

| 大模型节点（模） | 确定性代码（码） |
|------------------|------------------|
| 理解用户意图 | 格式和结构校验 |
| 处理模糊判断 | 数学计算和规则判断 |
| 生成和归纳内容 | 权限控制和副作用收口 |
| 在开放空间中规划 | 路由、重试和停止条件 |

### 5. 权限治理：工作图灵活，角色图稳定

治理拆成两个视角，各司其职：

- **工作图（路：怎么做）**：任务如何拆分 / 哪些步骤可以并行 / 下一步执行哪个节点 / 失败后如何调整计划
- **角色图（权：能做什么）**：谁能修改数据库 / 谁能调用外部接口 / 谁能执行高风险动作 / 哪些操作必须人工审批

> 工作图可以随任务灵活变化，角色图必须稳定可控——**路线可以改，权限不能松**。

### 6. 多智能体协作：从消息聊天到共享状态驱动

节点协作方式直接决定 Token 成本与可观测性，详见 [[共享状态驱动协作]]。

> **节点不必讲长故事，只更新必要字段。**

### 7. 状态持久化：四种关键能力

状态落盘不是可选项，详见 [[状态持久化四能力]]：人在回路、长周期记忆、状态回放、精准重试。

## 可靠性三原则

稳定性来自确定性设计，而不是节点数量：

1. **规｜规则代码化**：格式校验、数学计算、权限控制、停止条件，尽量交给确定性代码，不要让模型判断（→ 原则4 确定性边界）
2. **验｜验证独立化**：生产和审核严格隔离，用干净上下文和独立标准做验证，避免同源判断偏差（→ 原则3 独立验证）
3. **态｜状态可恢复**：通过检查点、执行记录和精准重试，把失败控制在最小范围（→ 原则7 状态持久化）

## 评价标准：只看真实世界的反馈

> **真实执行结果，才是智能体闭环的终点。** 模型口头"完成"不算数。

每类任务的现实锚点：

| 任务类型 | 现实锚点 |
|----------|----------|
| 代码完成 | 单元测试真正通过 |
| 数据更新 | 事务成功提交 |
| 工单解决 | 用户行为和反馈确认 |
| 消息发送 | 外部系统返回送达回执 |

三点评价原则：

1. **测｜测试真的通过**：结果可复现，不是模型声称正确
2. **标｜业务指标真的改善**：看完整业务结果，而不是单一代理指标
3. **人｜用户真的受益**：真实行为和反馈才是系统的现实锚点

> 如果所有"成功"都只是模型自己说的，那系统可能什么都没有完成。
