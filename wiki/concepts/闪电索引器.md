# 闪电索引器

## 核心结论

闪电索引器是 DSA 的索引打分部件，64 头 × 128 维 FP8，对 query 与历史 token 的每一对给出标量相关性分数，只把分数最高的 Top-k 个 KV 条目送进精确注意力。它头数少、维度小、精度低，用 FP8 执行，是"廉价预筛"能成立的前提。

## 要点拆解

### 索引打分公式

索引器对 query token $\mathbf{h}_t$ 与历史 token $\mathbf{h}_s$ 给出一个标量分数，形式上是多个索引头的 ReLU 加权和：

$$I_{t,s}=\sum_{j=1}^{H_I} w^{I}_{t,j}\cdot \mathrm{ReLU}\left(\mathbf{q}^{I}_{t,j}\cdot \mathbf{k}^{I}_{s}\right)$$

其中 $H_I$ 为索引头数，$\mathbf{q}^{I}_{t,j}\in\mathbb{R}^{d_I}$ 与权重 $w^{I}_{t,j}$ 由 $\mathbf{h}_t$ 投影得到，$\mathbf{k}^{I}_{s}\in\mathbb{R}^{d_I}$ 由 $\mathbf{h}_s$ 投影得到 [[1]](#ref-1)。

### 配置参数

落到具体配置上，索引头数为 64、每头维度 128、每 query 取 2048 个 KV 条目 [[12]](#ref-12)。按官方配置，索引侧是 64 个索引头、每头 128 维（`index_n_heads=64`、`index_head_dim=128`），索引 Key 则只有一份、由所有头共享（`kv_cache_num_heads=1`），最后由可学习权重把 64 个头的分数加权求和成一个标量 [[12]](#ref-12) [[16]](#ref-16)。

### 常见误读

常见误读是把这里的维度记成"64 维 Query"。头数少、维度小、精度低，是它便宜的全部原因 [[1]](#ref-1)。

### ReLU 取舍

技术报告对激活函数只给了一句解释：选择 ReLU 是出于吞吐考虑 [[1]](#ref-1)，并没有声称"实测精度更好"。这句简短的话背后有三重工程含义：ReLU 不产生全局归一化，省掉一行 softmax 与随之而来的全序列最大值规约；逐元素非线性可完全分块，不依赖跨块统计量；输出恒非负、分布右偏，量化到 FP8 时动态范围容易压住【推导】。索引打分在官方内核中采用 FP8 执行，省算力、省带宽，这是"廉价预筛"能成立的前提 [[1]](#ref-1) [[16]](#ref-16)。

### 复杂度账本

算清楚复杂度才不会被"线性注意力"的说法误导。主注意力的计算从 $O(L^2)$ 降到 $O(Lk)$，$k$ 是常数，上下文越长收益越大；但索引器本身仍要对每个 query 扫一遍全部历史，复杂度是 $O(L^2 H_I d_I)$，只是 $H_I$ 与 $d_I$ 都远小于主注意力，且用 FP8 执行，常数小了一到两个数量级 [[1]](#ref-1)【推导】。

因此严格说，DSA 是"二次项被降权"而不是"二次项消失"。在 128K 这一量级，索引器的开销可以忽略；若上下文继续拉长几个数量级，它会重新变成主要瓶颈，这与"Top-k 预算固定"一起构成 DSA 的天然边界 [[1]](#ref-1)【推导】。
