# 向量数据库

## 核心结论

- **代表产品**：Chroma、Milvus、Qdrant、Pinecone（专业向量库）；PostgreSQL 可用 pgvector 插件，但本质只是给关系库加向量能力，**大规模千万/亿级检索性能弱于专业向量库**。
- **存储对象**：向量 Embedding + 元数据（原文、ID、时间、标签）。
- **核心能力**：海量向量快速相似度检索（ANN），支持「向量检索 + 元数据过滤」——例如找与问题向量最相似的文档且只筛选某年发布的。
- **不擅长**：复杂事务、多表 join、精确业务查询。

## 与 RAG 的关系

- RAG 完整链路：文档 → 切分 chunk → Embedding 转向量 → 存入向量库；用户提问 → 问题转向量 → 向量库检索 TopN 相似文档 → 丢给 LLM 生成答案。
- 线上落地常按五层组合拳构建：HNSW 粗召回 + Int8 量化 + 元数据过滤 + TopK 控制 + Rerank 精排。→ [[RAG检索优化五层]]
