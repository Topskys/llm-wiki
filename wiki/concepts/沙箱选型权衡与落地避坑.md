# 沙箱选型权衡与落地避坑

## 核心结论

**本地与云端是两条路线，不是同一维度的高低**——前者用 OS 原语加代理与审批，开销近零但共享个人机器；后者用 microVM 或 gVisor，隔离强、可并行扩展，但有往返延迟与成本。

而落地阶段最常见的错误，是把**单条防线**当成**整体安全**。

## 要点拆解

### 一条路线判据

| | 本地 Coding Agent | 云端沙箱即服务 |
|---|---|---|
| 载体 | [[OS原语沙箱机制]] + 网络代理 + 审批 | [[Firecracker微虚拟机]] 或 [[gVisor用户态内核]] |
| 开销 | 近零，冷启动毫秒级 | 往返延迟 + 按量成本 |
| 边界 | 共享个人机器，非敌对多租户 | 隔离强、可并行扩展，面向多租户不可信代码 |

两条线各自收敛出了代表性产品，逐项对照见 [[Agent沙箱平台横评]]。

### 三条误区

**误区 1：设置只读根目录就等于安全**

即便根目录只读，只要临时目录可写且允许联网，Agent 仍能下载恶意工具；**必须叠加系统调用过滤与网络白名单**。这与 [[OS原语沙箱机制]] 中「单靠文件语义约束不够、需补网络出口」的结论一致。

**误区 2：放到远端容器就高枕无忧**

远端只是运行位置，**权限缺失照样逃逸**；即便 E2B 这类年千万级执行量的商用平台，也必须配套严格策略，不能放任权限全开。这条与 [[容器逃逸与沙箱绕过]] 的「容器已知不充分」互为表里。

**误区 3：Agent 程序可以捕获全部异常**

资源超限被内核强制杀死（**退出码 137**）时，Agent 收不到异常回调，**必须外置监控兜底**。这正对应 [[沙箱四层技术栈]] 可观测层的独立监控职责。

### 把三条串起来的立场

> **沙箱是概率性降低损失，不是绝对保证。**

Firecracker 无已知逃逸 CVE 不代表不可能，Seatbelt 的 profile 易写错，域名白名单也可能被 domain fronting 一类技巧绕过——所以四层栈的可观测层才必须**禁止 Agent 自证安全**。
