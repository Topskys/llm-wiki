# 微调与RAG分工

## 核心结论
- 一句话策略：**微调管「怎么说」，RAG 管「知道什么」**。
- 微调学习的是**销售话术、语气、转化引导与多轮风格**；RAG 注入的是**实时商品参数、价格政策、Care 条款、活动规则**。
- 业务价值：**新品上架、活动更新只更向量库，不用重训模型**——这是「微调 + RAG 双轨」的核心收益。

## 要点拆解

### 分工对比
| | 微调 | RAG |
|--|------|-----|
| 擅长 | 语气、转化引导、多轮风格 | 参数、价格政策、Care 条款 |
| 更新成本 | 高（重新训练/部署） | 低（重新入库 upsert） |
| 数据来源 | SFT 多轮对话集（[[DataBus]] 导出） | knowledge_chunks 结构化知识 |
| 失败模式 | 全量记住事实会过时/幻觉 | 无话术风格，回答生硬 |

### 为什么两者都必要
- 纯微调：知识更新要重训，活动一变就答错（「活动/新品知识变了要重训吗？」→ **不要**，更 DataBus→Milvus 即可）。
- 纯 RAG：模型不懂商城话术，回答不像销售，系统 prompt 冗长影响 [[TTFT首字延迟优化|TTFT]]。
- 只有**话术风格大变**（如品牌调性重塑）才考虑重训 SFT/DPO。

### 落地表现（灵购 AI）
- ModelForge 微调后话术在模型里，**system 可缩短 → prefill 更短 → TTFT 受益**。
- 灵购一次问答：回调服务 RAG 检索知识与微调模型流式生成，SSE 回 RTC。

### 常见追问口径
- 「微调和 RAG 矛盾吗？」→ **不矛盾**：微调=风格，RAG=事实。
- 「大促知识变了要重训吗？」→ **不要**；更 DataBus → Milvus 即可。
