# 结构化上下文

## 核心结论

扁平自然语言上下文在三弊：**歧义性**（不同指令相互混淆）、**注意力稀释**（关键信息淹没）、**跨引用困难**（多层嵌套难以定位）。结构化方案用 XML 标签对上下文分区，把"一段文本"变成"可寻址的层级结构"，显著提升模型利用率。

## XML 分区方案

```xml
<context>
  <system><role>…</role><constraints><constraint priority="critical">…</constraint></constraints></system>
  <environment><os>…</os><workspace>…</workspace></environment>
  <relevant_memories><memory id="mem_001" relevance="0.92">…</memory></relevant_memories>
  <conversation>
    <tool_call id="tc_1" name="read_file"><parameters>…</parameters></tool_call>
    <tool_result id="tr_1" for="tc_1"><content>…</content><metadata><lines>342</lines></metadata></tool_result>
  </conversation>
</context>
```

## 结构化四收益

| 收益 | 机制 |
|---|---|
| 注意力引导 | XML 标签作"锚点"，指引模型关注特定区域 |
| 可控截断 | 按标签块精确裁剪，而非粗暴按 token 数切割 |
| 可解析性 | 上下文可被程序化解析、验证、调试 |
| 层级化优先级 | 通过标签嵌套（如 priority 属性）表达重要程度 |

## 官方印证与补充

- Anthropic 官方实践一致：用 XML 区分指令、上下文与变量输入；长文档任务先要求模型**引文锚定**再执行任务。
- 注意陷阱：工具结果若内含 XML 标签会破坏结构（嵌套地狱），需转义或用 CDATA 包裹。
