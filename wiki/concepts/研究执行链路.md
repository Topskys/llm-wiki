# 研究执行链路

```mermaid
flowchart LR
    A["1 规划<br/>拆解子任务"] --> B["2 检索<br/>发出请求"]
    B --> C["3 阅读<br/>抽取证据片段"]
    C --> D["4 反思<br/>判断够不够"]
    D -- "不足则追加" --> B
    D --> E["5 综合<br/>组织报告并标注引用"]
    E --> F["可交付初稿"]
```

## 核心结论

一次研究可拆为五步循环，反复执行至模型判断材料足够。

**终止条件由模型自行判定，没有固定轮次上限**——这是它区别于固定流水线的又一表现。

## 要点拆解

### 五步与产出

| 步骤 | 动作 | 产出 |
|---|---|---|
| 1 规划 | 拆解问题为子任务，决定先查什么 | 检索计划 |
| 2 检索 | 发出搜索请求 | 候选页面列表 |
| 3 阅读 | 打开页面抽取关键信息，含 PDF 与图片 | 证据片段 |
| 4 反思 | 判断信息是否足够、缺什么 | 下一轮检索意图 |
| 5 综合 | 组织成报告并标注引用 | 可交付初稿 |

### 工具三类能力

| 能力 | 作用 | 关键点 |
|---|---|---|
| 网页浏览 | 搜索、点击、滚动、解析文件 | 覆盖公开网页，触达不到墙后内容 |
| 沙箱 Python | 真实执行计算与绘图 | 而非生成一段「描述计算结果」的文字 |
| 用户上传文件 | 与网络材料一并分析 | 私有材料与公开材料同场比对 |

沙箱执行是常被低估的一环：它让报告里的数字来自真跑一遍，而不是语言模型凭印象写出。相关机制见 [[Agent沙箱定义与安全价值]]。

### 上下文压缩为什么是必需品

放开轮次会带来上下文膨胀，数十个网页全文无法塞入上下文窗口。因此链路中必须有压缩环节，把已读内容提炼为证据笔记，丢弃冗余，仅保留可引用的证据。

这直接决定了耗时的量级差异：OpenAI 单任务通常 5–30 分钟，以速度为导向的方案可在 3 分钟内交付。**二者是设计取舍，不是优劣**。压缩手段本身参见 [[上下文压缩与摘要策略]]。

### 与通用 Agent 循环的关系

这五步是 [[Agent循环]] 在「研究」这一任务域上的具体形态：同样是收集上下文、采取行动、验证结果的循环，区别在于每轮动作是检索与阅读，终止条件是「材料足够」而非任务完成判定。
