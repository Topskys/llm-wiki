# 元数据规范（Frontmatter）

## 核心结论
- 每个 Wiki 页面头部必须携带 Frontmatter，它是检索、治理、AI 快速理解页面的基础。
- 两大硬约束：`created_at` **首次创建后永久不可改**；`source` 用双链指向原始素材支持溯源。
- `description` 直接复用为 `index.md` 的摘要，AI 据此快速判断页面相关性、无需读全文。

## 要点拆解

| 字段 | 约束规则 |
|---|---|
| `type` | 仅 7 种取值：concept / entity / overview / comparison / source_summary / topic / conflict |
| `source` | Obsidian 双链指向原始素材或来源页面 |
| `description` | 必填，1-3 句话，index.md 摘要直接复用此字段 |
| `created_at` | 页面首次创建时间，任何更新永久不可修改 |
| `updated_at` | 每次 Ingest、修正、回写均刷新为当前时间 |
| `tags` | 统一小写蛇形命名（如 `knowledge_base`），避免同义标签爆炸 |

- 时间格式统一 `YYYY-MM-DD hh:mm:ss`（24 小时制），如 `2026-09-05 14:30:00`。
- 检索能力：原生搜索仅做字符串匹配；安装 Dataview 并开启时间解析后，`created_at`/`updated_at` 才能支持时间区间运算、排序、统计。
