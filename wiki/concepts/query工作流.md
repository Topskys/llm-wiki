# Query 工作流

## 流程总览

```mermaid
flowchart TD
    A["用户提问"] --> B["读 index.md 定位主题"]
    B --> C["读取对应 Wiki 页面生成答案"]
    C --> D["结论先行 + 各观点标注来源双链"]
    D --> E{"有长期复用价值?"}
    E -->|"否"| N["仅对话输出，不入库"]
    E -->|"是"| F["回写 source_summary + tags 加 query_write"]
    F --> G["更新 index.md + shturl.md"]
    C -->|"wiki 未命中"| H["缺口与四层回退"]
```

## 核心结论
- **Query**（问答回写）＝基于已编译 Wiki 知识库回答问题，高质量答案再反哺知识库，形成「越用越完整」的闭环。
- 回答要求**结论先行**，每个观点标注 `[[来源页面]]`；库中无内容如实告知、禁止编造，推测内容标【推导】并绑定来源。
- 只有**具备长期复用价值**的答案才回写为 `source_summary` 页面，`tags` 追加 `query_write` 标签，便于月度治理优先复核质量。

## 要点拆解
1. **定位主题**：优先读取 `index.md`，通过 description 快速定位相关主题页面。
2. **读取内容**：综合读取对应 Wiki 页面生成答案；**非必要不读取 raw 原始素材**，保障查询效率。
3. **生成答案**：结论先行 + 来源标注；不同页面观点冲突时 Agent 先自行调和（核对依据、附【当前采信结论】并告知用户），无法调和才并列双方交人工。
4. **延伸推荐**：末尾输出 2-3 个高度相关的延伸主题及 Wiki 链接。
5. **回写判断与执行**：需回写时新建页面，type 统一为 `source_summary`，同步更新 index.md 与 shturl.md。

## 缺口与四层回退

wiki 未命中时按「L1 本地 wiki → L2 raw/本地项目信息 → L3 联网 → 兜底」逐层下探，**命中即停**，按命中层标注来源（wiki 双链 > raw 双链 > 项目路径 > 互联网外链）。

```mermaid
flowchart TD
    U["用户提问"]
    L1{"L1 本地 wiki 命中且足够?"}
    L1Y["基于 wiki 作答，标双链，结束"]
    L2{"L2 raw / 本地项目其他信息<br/>并行检索，是否命中?"}
    L2Y["作答，标注命中层来源"]
    V{"有长期复用价值?"}
    NOW["仅本次对话，不入库"]
    CONFL{"入库内容与 wiki 已有结论冲突?"}
    TAG["Agent先自行调和：核依据判断采信<br/>告知用户；无法调和才标⚠️交人工"]
    GO["Ingest → 人工抽检验收 → 入库<br/>更新 index / shturl"]
    L3{"L3 联网兜底，是否找到可靠网页?"}
    WEB["网页存 raw/articles，同上判定"]
    LAST["兜底：组合推理标推导<br/>→ 反问用户补料 → 登记缺口看板"]

    U --> L1
    L1 -->|"是"| L1Y
    L1 -->|"否"| L2
    L2 -->|"命中"| L2Y --> V
    L2 -->|"未命中"| L3
    L3 -->|"找到"| WEB --> V
    L3 -->|"无"| LAST
    V -->|"否"| NOW
    V -->|"是"| CONFL
    CONFL -->|"冲突"| TAG --> GO
    CONFL -->|"无冲突"| GO
```

要点：

- **L1**：wiki 命中且证据足够，直接基于 wiki 作答，**禁止联网**。
- **L2**：raw 素材与本地项目其他信息并行检索，命中即答并标注来源；有用价值判定。
- **L3**：联网抓取的网页存入 `raw/articles/`（只增不改），禁止直接写入 wiki、禁止粘贴摘要。
- **价值判定**：有长期复用价值 → Ingest + 人工抽检验收入库；无价值 → 仅本次对话，不入库。
- **冲突**：判定有价值但内容与 wiki 已有结论语义冲突 → Agent 先自行调和：核对依据、附【当前采信结论】并告知用户；无法调和才标 `⚠️观点冲突` 留双方原文交人工裁决，不自动覆盖（与 [[lint工作流]] 的冲突处置原则一致）。
- **兜底**：组合推理（标【推导】）→ 反问用户补料 → 登记缺口看板 `raw/_pending/`，素材到位后触发 Ingest。
