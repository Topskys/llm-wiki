# 文档智能能力边界

## 简介

文档智能并非万能，其能力边界是设计约束而非缺陷。理解这些边界才知道何时用文档智能、何时需要人工与校验兜底。出处：[[文档智能]] 素材第十章。

## 六条能力边界

| 边界 | 含义 | 工程启示 |
|---|---|---|
| 字符准 ≠ 业务对 | 识别准只是起点，字段级正确才有业务价值 | 必须延伸到理解/校验/驱动（连带 [[文档智能校验三支柱]]） |
| 多模态不是银弹 | 端到端 VLM 有 token 冗余、幻觉、分辨率三碍 | 解耦式多阶段优先（见 [[文档VLM三大范式]]） |
| 审核环节不能省 | 机器无法完全替代人工审核 | 低置信度转人工、结果反哺模型 |
| 绝对准确不可达 | 复杂难例（手写、无线表、异形表）无法 100% | 接受概率性，用置信度与溯源兜底 |
| 模型上限由数据决定 | 训练分布决定泛化能力 | 版式敏感，换模板需重新评估 |
| 文档是 Agent 的感官 | 文档是 Agent 理解世界的输入通道之一 | 结合 [[文档智能工程落地]] 的 RAG 与 Agent 接入 |

## 深层关联

- **字符准 ≠ 业务对**：源于 [[OCR文档解析]] 的"语义缺失"局限——字符准确率 99% 但字段错误照样致命，这是 [[文档智能]] 四段能力链成立的根本原因。
- **多模态不是银弹**：对应 [[文档VLM三大范式]] 端到端的三个结构性障碍，解耦式是务实解法。
- **审核环节不能省**：与 [[文档智能校验三支柱]] 的"抽取—规则校验—转人工"闭环节点互为表里。
- **文档是 Agent 的感官**：把文档智能接入 Agent（见 [[文档智能工程落地]] 的 Agent 接入），文档成为外部世界的结构化输入。
