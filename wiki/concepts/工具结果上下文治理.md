# 工具结果上下文治理

## 核心结论

长对话中最消耗窗口的是**工具调用结果**——一次网页抓取可达 50k tokens，常年占窗口 50% 以上，是"上下文污染"的物理来源。治理三板斧：**分类截断**（入口减量）、**链折叠**（跨步聚合）、**context editing**（动态清场）。

## 分类截断策略

| 工具类型 | 截断策略 | 保留上限 |
|---|---|---|
| 网络搜索 | 限量并合并重复结果 | 前 3–5 条 |
| 文件读取 | 只保留文件头/尾与关键段落 | 前 30 行 + 尾 30 行 |
| Shell 执行 | 只保留错误信息与退出码优先 | stderr 优先 |
| 数据库查询 | 只保留字段级 Schema 裁剪 | 按列裁剪 |
| 内部知识库 | 返回摘要而非全文 | 摘要 + 引用 id |

## 链折叠与 context editing

- **链折叠**：多步工具调用（读文件→提取数据→写结果）链式折叠为一个统一摘要，跨步上下文聚合，避免"读 100 行→引 3 处→留 97 行垃圾"。
- **context editing（Anthropic 实测）**：先精确识别小段陈旧输出，再用"编辑动作"删除它，避免整块回退；100 轮网页搜索任务 token 消耗降 **84%**，本会因耗尽失败的工作流得以完成。
- **自失效机制**：工具结果有一定"保质期"，超时自动失效重取，防止决策基于陈旧数据。

## 治理管道

```
原始输出 → 分类截断（按工具类型规则）→ 链折叠（跨步聚合）→ context editing（动态清场）→ 进窗口
```
