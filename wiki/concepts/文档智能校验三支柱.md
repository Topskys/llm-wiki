# 文档智能校验三支柱

## 简介

**可校验**是文档智能区别于普通 OCR 的核心：数据必须能被追问。三支柱缺一不可，属 [[文档智能]] 四段能力链的"校验"段。

## 三支柱

| 支柱 | 机制 | 作用 |
|---|---|---|
| 置信度 | 字段级 confidence 输出，阈值经离线标注与线上 A/B 标定 | 低置信度自动路由到人工队列 |
| 溯源 | page_no 与 bbox 坐标、原文引用可回溯 | 让答案可核验而非盲信模型 |
| 规则校验 | 业务一致性（价税合计等于金额加税额）、跨单据对齐、Schema 校验 | 拦截语义层面的错误 |

## 五步法落地

```mermaid
flowchart LR
    A["① 采集<br/>汇聚单据 · 统一格式命名"] --> B["② 分类<br/>判断类型 · 分流"]
    B --> C["③ 提取<br/>多模态抽关键字段<br/>而非整页 OCR"]
    C --> D["④ 审核<br/>业务规则校验<br/>低置信度转人工"]
    D --> E["⑤ 录入<br/>回写 ERP / 财务中台"]
    style D fill:#117C88,color:#fff,stroke:#0A5A63
```

1. **采集**：汇聚单据，统一格式与命名
2. **分类**：判断类型并分流
3. **提取**：多模态抽关键字段，而非整页 OCR
4. **审核**：按业务规则校验，低置信度转人工
5. **录入**：回写 ERP 或财务中台

## 审核环节不能省

**审核环节不能省**是实践共识。生产环境的兜底闭环是"**抽取—规则校验—转人工**"：模型给每个字段打置信度，低于阈值的连同上下文推给业务人员确认，结果再反哺模型。这才是生产环境跑得稳的组合——呼应 [[文档智能能力边界]] 中"审核环节不能省"一条。
