# 稀疏注意力适用边界

## 核心结论

稀疏注意力适用边界描述 DSA 在短上下文、超长上下文、部署门槛、显存、能力波动五个维度的边界与应对。Top-k 收敛了单步计算，但没有约束生成长度。

## 要点拆解

### 边界与应对

表3 汇总了 DSA 的适用边界与应对：

| 边界 | 具体表现 | 应对 |
|---|---|---|
| 短上下文 | $k$ 固定 2048，短序列退化为稠密，稀疏收益趋零 | 走 masked MHA 路径，不必强上稀疏内核 |
| 超长上下文 | 索引器仍是 $O(L^2)$ 打分，会成为新瓶颈 | 配合上下文管理，或叠加分块检索 |
| 部署门槛 | 动态 Top-k 需专用内核与分页支持 | 依赖 SGLang、vLLM 等已适配框架 |
| 显存 | 索引器另存单头 128 维 key 缓存 | 主 KV 不变，但需预留这部分余量 |
| 能力波动 | 部分推理基准小幅回退 | 补推理预算或经后训练修复 |

### 成本结构

最直观的验证来自价格：V3.2-Exp 上线当日 API 价格下调 50% 以上 [[3]](#ref-3)。技术报告给出 H800 集群、按 2 美元每 GPU 小时计的成本曲线：预填充与解码的单位 token 成本都随位置增长而抬升，但 V3.2-Exp 的曲线在长位置显著低于 V3.1-Terminus [[1]](#ref-1)。机制上，预填充省的是注意力算力，解码省的是 KV 访存（从每步读全量历史降为读 2048 条），所以上下文越长差距越大 [[1]](#ref-1)【推导】。

### 短序列的小幅回退

短序列预填充改用 masked MHA 模式模拟 DSA，说明收益与长度强相关，短文本并不在稀疏路径的甜点区 [[1]](#ref-1)。表2 中 GPQA-Diamond、HLE、HMMT 2025 三项下滑，官方的归因不是稀疏注意力伤到了能力，而是这一批评测里 V3.2-Exp 生成的推理链更短；补上推理预算后差距收敛 [[1]](#ref-1)。
