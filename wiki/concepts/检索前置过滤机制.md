# 检索前置过滤机制

## 核心结论

- **核心机制**：权限标签作为标量过滤条件下发到向量引擎层，在相似度计算前先过滤无权限 Chunk。
- **关键原则**：过滤逻辑下推到向量引擎层，不是召回全部再在业务代码里循环过滤。
- **前提条件**：向量数据库需支持 metadata 标量过滤。

## 要点拆解

### 检索流程
1. 网关鉴权，获取用户身份及权限标签
2. 检索请求携带权限标签作为标量过滤条件
3. 向量库先过滤无权限 Chunk，仅在有权范围内执行相似度计算和 TopK 召回

### 反模式：先召回再过滤 → 检索漏斗坍塌
若先召回全部相似 Chunk 再在业务层剔除无权限数据，高相似度的无权限文档将占据 TopK 名额，有权限内容被挤出召回列表，导致：
- 召回质量下降（有效内容变少）
- 存在泄露风险（无权限数据曾被召回）

### 代码示例
```python
user = authenticate(request)
user_perms = permission_center.get_roles(user.id)

results = vector_db.search(
    query_vector=encoding_model.encode(query),
    filter={
        "tenant_id": user.tenant_id,
        "dept_id": {"$in": user.dept_ids},
        "roles": {"$in": user_perms}
    },
    limit=top_k
)
```
