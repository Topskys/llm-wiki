# 过程审计

## 核心结论

前三层都只解释单次输出，Agent 却把任务拆成几十步工具调用，只看最后一步不够。过程审计（process audit）不解释神经元，而是保证**事后能复现决策链**。这层最容易被低估，却最该先做【推导】——它的价值在于不依赖模型配合：理由可以不忠实（见 [[忠实性]]），日志与概率分布仍然真实。

## 要点拆解

### 四件套

| 手段 | 做法 | 关键点 |
|---|---|---|
| 全轨迹日志 | 工具调用、入参、返回值、耗时、token 消耗全部落盘 | 支持回放，同一轨迹重跑看决策链能否复现 |
| 动作概率 | 架构上把动作做成特殊 token，直接读候选分布 | 比事后追问模型可靠得多 |
| 分级审批 | 高风险动作强制人工确认 | 把不可解释的部分挡在人在回路之外 |
| 意图监测 | 把思维链当监控信号扫一遍，命中可疑模式升级人工 | 要接受它漏报 [[1]](#ref-1) |

### 与 Agent 可观测性的衔接

过程审计是四层方法里最贴合工程日常的一层，与 [[Agent可观测追踪三轴]] 的审计轴同构：都强调不可重建、事后可回放；与 RAG 中的 [[审计与越权监控]] 同属「先留痕、后追责」路线（见 [[MCP安全最佳实践]] 的全链路审计原则）。

### 边界

日志可被训练绕过——若模型学会把危险意图写在日志之外，过程层同样失守，这正是 [[忠实性]] 页 Korbak 结论的 Agent 版。
