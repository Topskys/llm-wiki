# 大模型兜底层

## 核心结论
- 定位：仅处理前两层置信度不足的约 5% 长尾复杂请求。
- 适用场景特征：表达模糊、歧义强、跨多任务、多步骤组合。
- 能力范围：不仅做意图分类，还完成任务拆解、工具选择、参数提取，通过函数调用（Function Calling）或 MCP 协议直接对接后端工具。

## 要点拆解

### 适用场景
- 表达模糊、歧义强
- 跨多任务、多步骤组合
- 需要任务拆解与工具选择

### 成本控制
- 该层延迟最高（500-2000ms）、成本最贵，定位是最后兜底防线，绝对不能扛主流量。
- 监控指标：LLM 兜底率 ≤8%，高于此值说明前两层过滤不够。

### 能力范围
- 意图分类
- 任务拆解
- 工具选择
- 参数提取
- 通过函数调用或 MCP 协议直接对接后端工具

## 边界澄清（易混概念）

⚠️ **本页「兜底层」与 [[RAG阈值拒答机制]] 中的「兜底层」同名不同义**：

| | 本页（意图识别分层漏斗） | RAG 质量体系的兜底层 |
|---|---|---|
| 层级位置 | 请求路由的**最后一层**（约 5% 长尾） | RAG 链路的**事后止损**环节 |
| 处理对象 | 置信度不足的复杂请求 | 不可靠的生成输出 |
| 手段 | 意图分类 / 任务拆解 / 工具调用 | 阈值拒答 / 人工复核 / 全链路日志 |
