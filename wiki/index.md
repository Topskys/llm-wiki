# Index — Wiki全局索引

> 用途：供AI快速检索全库页面，每条附带一句话核心摘要。
> 维护规则：Ingest/回写后自动更新；摘要复用页面Frontmatter的description字段；_archive页面不纳入索引。

---

## entities 实体

- [[karpathy]]：LLM-Wiki 个人知识库框架的提出者，主张由 AI 承担知识编译劳动、人类聚焦思考与决策。目前素材仅一笔带过，背景信息待后续补充。
- [[LLM-Wiki框架]]：基于 Karpathy 思想、以 Obsidian + Git 落地的一套 AI 编译型个人知识库框架，核心是 raw 原始素材层、wiki 编译知识层、SCHEMA 规则契约层的三层架构。
- [[灵购AI]]：商城智能语音客服平台；商品知识库 + RTC 7×24 语音，CustomLLM 回调服务的 RAG 检索与微调模型流式推理，用户主负责项目。
- [[DataBus]]：全域 AI 业务数据中台；汇聚多源对话与商品文档，ETL 五层流水线产出 SFT 训练集与 RAG 知识库素材，并接收 Agent 数据回流。
- [[ModelForge-AI]]：电商自有化模型微调工厂；本地 QLoRA 验证 + 云端量产（SFT+DPO），搭建 Embedding 粗召回→Cross-Encoder 精排的三段式检索。
- [[LiveClip-AI]]：直播切片智能剪辑 Agent；FFmpeg.wasm 轻量压缩上传，PostgreSQL 自研任务队列调度 ASR+大模型识别高光片段，批量产出短视频。
- [[MultiVis-AI]]：图文视频一体化自媒体运营 Agent；LangGraph 三子图 + PostgreSQL Checkpointer 节点级故障自愈，SSE 流式输出 + 多模型路由降本。
- [[cc-switch]]：跨平台开源 AI 编程工具配置管理总控台（farion1231/cc-switch），统一管理 Claude Code / Codex / Gemini CLI / OpenCode 的 provider、MCP、prompts、skills，v3.16.0 起本地路由支持把第三方模型接入 Codex。
- [[vLLM]]：伯克利高吞吐 LLM 推理引擎，SOSP 2023 的 PagedAttention 分页管理消除显存碎片；显存不足时整页换出到 CPU 内存，两级存储适用于中等长度序列。
- [[Medusa]]：投机解码的附加预测头方案：在目标模型头部加多个并行 decoding head、一次预测多个未来 token 作草稿，省去独立小模型部署；曾在 vLLM 主导，现相对被 EAGLE 等替代。
- [[EAGLE]]：投机解码的特征级自回归草稿方案，复用目标特征做草稿；EAGLE-2 动态树形草稿、EAGLE-3 直接 token 预测融合多层特征，五项任务最高 6.5× 加速、较 EAGLE-2 提升约 1.4×，是当前 vLLM 投机解码核心支持方向。
- [[SpecForge]]：LMSYS 开源的投机解码统一栈，把"围绕目标采集特征→训练草稿→导出"变成可复用流水线，支持 EAGLE3、DFlash、Domino 等算法并开源多款草稿模型，推动草稿训练系统化。
- [[FlexGen]]：2023 ICML 单 GPU 高吞吐生成推理框架，GPU/CPU/SSD 三级存储 + 线性规划求解最优换入换出调度，面向单请求长上下文。
- [[InfiniGen]]：2024 OSDI 的动态 KV Cache 管理系统，学习注意力模式预测未来访问并提前预取，减少换入等待，适用于多轮对话场景。
- [[Mooncake]]：以 KVCache 为中心的分离式 LLM 服务架构，KV 独立存储池支持跨请求跨卡共享，全局调度加预取，面向高并发与长上下文。
- [[FrugalGPT]]：斯坦福大学 2023 年提出的 LLM 成本优化框架，通过路由器+质量估计器+停止判断器三组件混合路由与级联，在保持质量的同时大幅降低成本。
- [[RouteLLM]]：LMSYS 2024 年提出的 LLM 路由框架，通过偏好数据训练路由器，在强模型与弱模型之间动态选择，优化成本与质量权衡。
- [[BPE分词算法]]：BPE（Byte Pair Encoding）是现代大模型最主流的分词算法，从字符级开始反复合并最高频相邻对，直到达到目标词表大小。
- [[RoPE旋转位置编码]]：RoPE（旋转位置编码）通过对 Q、K 做角度正比于位置的旋转变换，使注意力得分仅依赖 token 间的相对位置差，是现代主流大模型的位置编码方案。
- [[MCP协议分层架构]]：MCP 协议栈分为传输层（Stdio/Streamable HTTP）与数据层（JSON-RPC 2.0），各层职责边界清晰、可独立演进。
- [[MCP无状态交互]]：MCP 2026-07-28 新版取消有状态会话，每请求在 _meta 字段携带协议版本与能力信息，通过 server/discover 替代 initialize 握手。
- [[MCP三层架构]]：Host（AI 应用）→ Client（连接器）→ Server（能力提供者）三层职责解耦，1:1 专用连接。
- [[MCP核心原语]]：Server 对外提供 Tools（可执行函数）/ Resources（只读上下文）/ Prompts（提示模板）三类标准化原语。
- [[MCP安全最佳实践]]：MCP Agent 开发安全六原则：最小权限、高风险确认、凭证隔离、输入校验、全链路审计、沙箱隔离。
- [[τ-bench]]：Sierra 提出的工具-智能体-用户交互基准，以数据库终态与人工标注目标状态比对判定成败，并提出 pass^k 指标；实测 gpt-4o 在 retail 域成功率不足 50%、pass^8 低于 25%，tau2-bench 已扩展到语音全双工等多模态评测。
- [[LiveBench]]：抗污染的动态 LLM 基准：题源取自近期数学竞赛、arXiv 论文、新闻与数据集，按客观 ground truth 自动判分，规避测试集污染与评委/众包偏差；覆盖六类共 18 个任务，头部模型准确率低于 70%，保持区分度。
- [[HarmBench]]：HarmBench 是自动化红队与鲁棒拒答方向的标准化评测框架，统一了攻击方法分类、目标行为分类学与量化指标定义（核心为攻击成功率 ASR），并以 18 种红队方法对比 33 个目标模型及防御，首次给出跨方法、跨模型的统一量化结论。
- [[PyRIT]]：PyRIT（Python Risk Identification Tool）是微软开源的自动化红队框架，把 GCG、红队语言模型等攻击编排为与模型和平台无关的自动化流水线，用于多模态生成式系统的规模化风险识别，是红队四步闭环中迭代阶段的工程化编排层。
- [[Constitutional Classifiers]]：Constitutional Classifiers 是 Anthropic 提出的分类器防御方案，用带宪法（constitution）约束的分类器拦截通用越狱；部署前接受超过 3000 小时人类红队对抗，结果显示没有攻击报告能在更严格判定阈值下成功回答全部 10 个目标问题，验证了对通用越狱的实际拦截能力，代价是可观测的过度拒绝。
- [[MinerU]]：上海人工智能实验室/OpenDataLab 开源的高精度文档解析引擎，MinerU 2.5 从模块化流水线转向 1.2B 参数解耦式解析 VLM，Stage I 整页版面分析 + Stage II 原生分辨率局部识别，输出 Markdown/JSON（带 bbox），在精度、算力与可解释性上取得平衡。
- [[Docling]]：IBM Research 开源的文档转换框架，以统一文档模型 DoclingDocument 为中枢 + 可插拔流水线，背后端/流水线/选项解耦，支持 Markdown/dict 导出与 HybridChunker RAG 分块，默认全本地不共享数据。
- [[OmniDocBench]]：文档解析与结构还原的公开权威基准，v1.6 含 1,651 页真实文档、八项官方指标，覆盖文本/表格/公式/版面检测等任务的精度评估，是衡量文档智能工具的公共标尺。
- [[MarkItDown]]：微软 AutoGen 开源的轻量级 Python 工具，把 PDF/Word/PPT/Excel/图片/音频/HTML 统一转成 LLM 友好的干净 Markdown，弱化二维版面建模、强化格式覆盖与 LLM 文本消费；GitHub 约 17.7 万 Star（Rank #43）、PyPI 月下载千万级，与 MinerU/Docling 构成文档智能三条工程路线。
- [[Jev 决策模型]]：TypeSafe AI 于 2026-09-15 发布的首个 System One 决策模型：输入程序状态+预定义问题，返回带校准概率的类型化决策，三种原语 Choice/Score/Boolean，约 70~500ms、低成本，用于 Agent 决策节点与批量结构化判断；权重未开放、独立数据待验证。
- [[TypeSafe AI]]：Jev 的研发公司，Diogo Almeida（ChatGPT 参与研发、RLHF 提出者之一）/Erik Gafni/Sasha Sheng 联合创办，发布首个 System One 模型 Jev 并获 DCVC 领投 4000 万美元种子轮。

## concepts 概念

- [[编译型知识库]]：将原始素材一次性预编译为原子化、可关联、可治理的知识网络，而非留存素材碎片的知识管理模式，是 LLM-Wiki 与普通 RAG 的核心分水岭。
- [[三层架构]]：Raw 原始素材层 / Wiki 知识编译层 / SCHEMA 规则契约层三层权责分离的架构，配套 index.md 索引与 shturl.md 变更日志两个 AI 元数据文件。
- [[ingest工作流]]：新素材摄入并联动编译整个 Wiki 知识网络的过程：准入判断、存 raw、AI 解析、联动更新 10-15 个页面、双链、冲突检测、同步索引日志、人工验收。
- [[query工作流]]：基于已编译 Wiki 进行问答并反向沉淀高质量答案的工作流：index 定位、读 Wiki 生成结论先行答案、有长期复用价值时以 source_summary + query_write 标签回写；wiki 未命中时 L1 wiki / L2 raw / L3 联网三路并行检索，按来源优先级 外链 > wiki > raw > 项目路径 取舍，L3 联网结果不落盘 raw。
- [[lint工作流]]：对全库做定期质量体检的工作流：按 P0 阻断 / P1 重要 / P2 优化三级输出问题清单与统计，只提建议、禁止自行修改 Wiki 文件。
- [[元数据规范]]：Wiki 页面强制携带的 Frontmatter 字段规范：type / source / description / created_at / updated_at / tags，其中 created_at 创建后永久不可修改。
- [[结构化垃圾场]]：AI 知识库失败模式：批量生成大量精美页面但无人阅读、无人校验，最终沦为无价值、只增不剪的归档坟场；核心应对是严格准入、先学原文再用 Wiki、月度治理裁剪。
- [[防膨胀闸门]]：控制知识库膨胀的三道机制：素材准入（仅长期复用才 Ingest）、数量控制（单素材 10-15 页）、定期裁剪（闲置页面归档），配合归档隔离避免无限堆积。
- [[RAG检索优化五层]]：在线检索优化组合拳：HNSW 要快、Int8 要省、元数据要准、Top20 要控、Rerank 要精，标准口径 Top20→Top5，命中率 72%→89%。
- [[Hybrid混合检索]]：粗召回阶段稠密语义路 + 稀疏关键词路并行、dense_weight 融合分数；精排不复算向量，dense_weight 在线预设、离线评测调参。
- [[Embedding向量嵌入]]：把非结构化数据（文本/图片/音频/视频）经模型转成固定长度浮点数数组（768/1536维），语义相近的内容在向量空间里距离更近，检索用余弦/欧氏相似度。
- [[向量数据库]]：向量 Embedding + 元数据的存储检索平台（Chroma/Milvus/Qdrant/Pinecone），用 HNSW/IVF/FAISS 等 ANN 索引做近似相似度检索，适合 RAG/图文检索/推荐；不擅长事务与多表 join。
- [[ANN近似最近邻搜索]]：向量库加速的底层机制：不扫全量、索引剪枝只搜小部分候选，牺牲一点召回率换毫秒级查询；HNSW/IVF/PQ 是其实现。
- [[HNSW图索引]]：层次化导航小世界 ANN 索引：多层跳表+图结构，高层稀疏点粗略导航、底层存全部向量，Milvus/Qdrant/Chroma 常用。
- [[IVF倒排索引]]：先聚类分桶再局部搜索的 ANN 索引：查询只算最近的少数桶（1000万→3万条），加速明显但可能漏检跨桶最相似向量。
- [[PQ乘积量化]]：把高维向量压缩成短编码省内存减 IO、距离计算变查表，代价是损失精度，与 ANN 的 trade-off 同向。
- [[向量搜索加速]]：向量搜索快的四个关键：ANN 剪枝（最大加速源）、向量量化、内存优先、SIMD 批量浮点运算；速度↔召回率是核心权衡。
- [[TTFT首字延迟优化]]：大模型首字延迟优化全景：RAG 压检索让 LLM 更早开跑、前缀缓存/KV Cache 减 prefill、prompt 精简、SSE 流式，首字 15s→2s。
- [[FEC与自适应JitterBuffer]]：RTC 音频传输层弱网优化：FEC 冗余抗丢包、自适应 Jitter Buffer 平滑抖动，与 RAG/TTFT 分属不同层级。
- [[微调与RAG分工]]：电商垂直场景模型策略：微调管「怎么说」（话术风格），RAG 管「知道什么」（实时业务知识），更新知识库不必重训模型。
- [[QLoRA与LoRA微调]]：参数高效微调：QLoRA 量化基座降显存单卡可训；本地验证（rank=64）+云端量产（rank=32）两阶段，SFT+DPO 盲评 2.1→4.3。
- [[LangGraph与Checkpointer工作流]]：LangGraph 子图编排 + PostgreSQL Checkpointer 节点级状态持久化，实现故障自愈与断点续跑，SSE 流式 + 多模型路由配套。
- [[committed-artifact]]：AI-native SDLC 的核心机制：每个阶段结束时向版本库提交一个 artifact（intent.md/spec.md/plan.md/diff+tests/PR+findings/incident），下一阶段从读它开始，commit 链同时充当审计轨迹。
- [[CLAUDE记忆文件]]：仓库根目录的 agent 记忆文件：给出新加入者需要的一切（命令/约定/架构/易错点），agent 每次会话开始即读取，全团队共享一份并随错误迭代。
- [[Skills技能]]：组织把制度知识可操作化的机制：显式、版本化、广泛适用、中心化更新的指令包，按需自动触发；是建议性控制，政策必须必然成立时需 hooks 兜底。
- [[Hooks护栏与审批门]]：agent 动作前的确定性控制层：build 阶段做护栏（保护路径/格式化/防密钥泄露）、deploy 阶段做强制的审批门（allow/ask/block），非不可商量的 hook 可被工程师关闭。
- [[plan模式]]：Claude Code plan mode 作为实现阶段的默认入口：给 agent 批准过的 spec.md，让其先产出可审查的实现计划（plan.md），人在计划层把关后再进入实现，实现偏离计划时同步更新。
- [[并行会话与子代理]]：一个工程师驱动多条并行工作流：parallel session（git worktree 隔离、互不可见、人负责 steering）+ subagent（会话内作用域助手、独立上下文），控制来自仓库配置，输出归属到发起人。
- [[Agent反馈闭环]]：给 agent 一个验证自己工作的机制：量化验收目标 + 反馈通道（测试/build/截图 diff），可先写失败测试再用 hook 保护它；与 verifier 子代理的区别在于它贯穿整个任务、在工程师看到前自修错误。
- [[持续评估]]：CI 中的持续评估：把近期真实任务固化为 eval 套件，在 CLAUDE.md/skills/hooks 等 agent 配置变更时自动回归，防止换模型/改提示词降低完成质量；生产事故也沉淀为回归 eval。
- [[AI代码评审]]：AI 双端参与 PR 评审：对入站 PR 按 REVIEW.md 分 pass 审查（bugs/security/compliance）、对自家 PR 响应 @claude 评审意见并推送修复；findings 不自动放行/拦截，approval 仅来自人类 branch protection。
- [[监控闭环]]：让 SDLC 闭环自主运转：确定性脚本监控生产指标控制带（1σ 记日志/2σ 只读诊断/3σ 提议修复），带置信门控触发 agent 写 intent.md 走正常管道；Claude Tag 把一线 on-call 纳入频道内闭环。
- [[阴阳燮理]]：三十六计的哲学根基：事物对立统一、相反相成的规律，是全部三十六计运筹的理论基础——计谋成败取决于能否正确把握阴阳变化规律。
- [[走为上]]：三十六计最后一计：敌我力量悬殊时有计划的主动撤退，保全实力、以退为进，出《南齐书·王敬则传》『走为上计』，重在保存火种而非消极逃跑。
- [[双层网关架构]]：Nginx+AI业务网关双层流量治理架构：边缘层管连接/安全/并发粗粒度，AI 网关层管鉴权/令牌桶/熔断/动态路由细粒度调度，职责分离解决 RPM+TPM 双配额调度难题。
- [[RPM与TPM联合令牌桶]]：RPM+TPM 联合配额两级令牌桶：本地桶接口/用户级快速预拦截、Redis 分布式桶全局权威防多实例超发，预扣预估 Token+响应后按请求ID退款的令牌生命周期管理。
- [[熔断器状态机]]：网关熔断器状态机：Closed/Open/Half-Open 三态，仅由 5xx 错误率驱动（429 走配额通道），SSE 以请求发起时刻计入滑动窗口，配半开探测与灰度回切闭环。
- [[429流量治理]]：429 流量治理：解析区分短时 RPM 超限/TPM 耗尽/月度配额用尽三类，前两者走配额感知切换（换同模型Key或降级）、月度用尽标记长期失效不重试再切，配滑动窗口计数防惊群。
- [[能力标签驱动降级]]：异构模型降级：能力标签体系驱动候选筛选，硬性标签（多模态/Function Call/上下文长度）必须满足、软性标签（速度/成本/质量）可放宽，allow_fallback 开关防 Agent 场景误降级。
- [[灰度回切]]：熔断/降级后的恢复路径：半开探针连续成功判定节点恢复后，不一次性全量切回，采用渐进式灰度放量（逐步提升回切流量比例）持续观测 429 与错误率，防瞬间流量冲击再触发限流。
- [[SSE流式容错]]：SSE 流式响应差异化容错：已开始输出即直接中断不重试不切节点，防止拼接内容语义断层；长流以发起时刻计入熔断统计；对流式请求的预扣 Token 按流结束真实 usage 结算。
- [[背压透传]]：不打破 TCP 背压，让其透传：下游写不进去时暂停读上游，上游 TCP 窗口自然收缩、网关自然减速，同步转发是最稳做法。

- [[慢消费者处置]]：监控每连接缓冲区水位、排空速率与连续写阻塞时长，越过阈值主动断开；配合断线续传把"内存里扛住慢消费者"转化为"随时安全断开"。

- [[审计与越权监控]]：RAG 权限隔离第五层：每次请求记录用户 ID、问题、召回 Chunk 列表、权限过滤条件、模型输出，出现多次越权检索行为触发告警，实现事后溯源和实时告警。
- [[分层权限模型]]：RAG 权限隔离三层权限粒度模型：租户隔离（tenant_id + 命名空间双重隔离）、角色/部门（dept_id + roles）、用户白名单（user_id），覆盖 SaaS 多客户、企业内部、机密文档三类场景。
- [[段落字段级权限细化]]：段落/字段级权限细化：元数据 schema 增加 section_id 和 field_name 维度，入库时按段落/字段独立标注权限，实现同一文档内不同段落或字段的差异化权限控制。
- [[诱导提问防御]]：RAG 权限隔离入口防线：意图识别模块识别套取涉密信息的提问，直接拦截高危 query，对应全链路架构图中的 A0 节点。
- [[工业级意图识别架构]]：工业级意图识别五模块混合架构：输入预处理（降噪）、多路并行识别分支（规则/轻量模型/大模型）、置信度聚合决策（阈值+投票+多意图）、后置校验过滤（白名单+槽位校验）、样本回流迭代（难例挖掘+增量微调）。
- [[多路并行识别]]：三路分支（规则/轻量模型/大模型）同时推理，非串行漏斗。
- [[置信度聚合决策]]：阈值/多路投票/多意图/优先级，低置信转人工。
- [[后置校验过滤]]：业务白名单 + 参数槽位校验，拦截越权调用。
- [[样本回流迭代]]：难例挖掘 + 增量微调 + 扩充向量库/规则库。
- [[PagedAttention分页内存]]：PagedAttention 借鉴操作系统虚拟内存分页，把 KV 缓存切成固定物理块并用块表维护逻辑到物理的映射，把内存浪费从 60%–80% 压到 4% 以下，是 vLLM 的核心技术与连续批处理的使能前提。
- [[GQA与MQA多头变体]]：MQA 与 GQA 通过减少 KV 头数从模型结构上压低 KV 缓存基数：GQA 用 G 个分组共享，G=H 退化为 MHA、G=1 退化为 MQA，是可在显存与质量之间连续平滑权衡的主流折中方案。
- [[MLA低秩潜在注意力]]：MLA（多头潜在注意力）不再缓存完整 K/V 向量，而是缓存低维隐向量、计算时投影回原空间；DeepSeek-V2 实测 KV 减少 93.3%、生成吞吐 5.76×、训练成本降 42.5%，是架构层压缩效率最高的方案。
- [[KVCache低比特量化]]：在不改模型结构的前提下降低 KV 存储精度线性减显存；KIVI 发现 Key 适合按通道、Value 适合按 Token 的非对称 2bit 量化，峰值显存降 2.6×、最大批 4×、吞吐 2.35–3.47×，是部署侧首选。
- [[FlashAttention算子优化]]：FlashAttention 是 IO 感知的注意力优化：Q/K/V 分块在片上 SRAM 累加、用在线 Softmax 让 N×N 中间矩阵不落盘，显存从 O(N²) 降到 O(N)，与所有 KV 优化完全正交、长上下文必开。
- [[Prefill与Decode两阶段]]：Prefill 算力密集、Decode 访存密集的资源不对称是推理调度的核心矛盾；由此派生 Chunked Prefill 防长 Prompt 阻塞与 PD 分离部署，整体吞吐可提升 30%–50%。
- [[分层漏斗路由]]：分层漏斗路由架构：规则层拦截约 60% 高频意图（<1ms），上下文层处理约 35% 多轮指代（~100ms），大模型层兜底约 5% 长尾请求，按请求复杂度递进分配算力。
- [[规则拦截层]]：规则拦截层：高频固定意图，毫秒级响应，完全不消耗大模型算力。技术手段为关键词匹配、正则表达式、有限状态机（FSM）。
- [[上下文状态层]]：上下文状态层：承接规则漏下的约 35% 流量，处理多轮对话中的省略指代场景。使用轻量小模型做语义分类与槽位填充，延迟约 100ms。
- [[大模型兜底层]]：大模型兜底层：仅处理前两层置信度不足的约 5% 长尾复杂请求。不仅做意图分类，还完成任务拆解、工具选择、参数提取，通过函数调用或 MCP 协议直接对接后端工具。
- [[置信度阈值]]：置信度阈值：上下文状态层输出置信度分数，低于阈值时升级至大模型兜底层。阈值通过离线标注集 + 线上 A/B 测试确定，0.7/0.8/0.9 三档分别对应成本最低/平衡点/准确率最高。
- [[意图评测]]：意图评测：分层漏斗的评测方法论，包括评测数据集构建（采样、标注、划分、难例挖掘）、评测指标（准确率、精确率、召回率、F1、混淆矩阵）、分层评测与在线评测（影子流量、人工抽检、反馈闭环）。
- [[门控路由与Top-K稀疏激活]]：MoE 层的数学形式化：y = Σ g_i(x)·FFN_i(x)，Top-K 稀疏门控只让被选中的 K 个专家参与计算、其余零激活；K 从 Shazeer Top-4、GShard Top-2、Switch Top-1 简化到 DeepSeek-V3 的 Top-8 路由 + 1 共享。
- [[路由范式谱系]]：MoE 路由与均衡方法的谱系：Token-Choice、Expert-Choice、软分配、确定性哈希四大范式，附 MMoE、ReMoE 变体与七种均衡方法的机制、优点与局限全景对比。
- [[稀疏激活与容量解耦]]：MoE 收益的本质来源：总参数决定知识容量、激活参数决定单 token 算力，两者解耦后以近恒定算力承载远超稠密模型的参数；配专家容量因子与 token 丢弃的工程约束。
- [[路由坍缩与赢家通吃]]：路由坍缩是 MoE 训练的头号失败模式：路由器早期的微弱优势经「赢家通吃」正反馈自我强化，最终少数专家包揽大部分 token、其余长期得不到训练信号，实际容量远小于名义容量。
- [[辅助均衡损失与Router z-loss]]：训练期的两个正则项：辅助均衡损失 α·N·Σ f_i·P_i 把负载均衡写进损失、简单成熟但干扰主任务梯度；Router z-loss 惩罚 logits 幅度防止 softmax 饱和，与均衡损失互补。
- [[无辅助损失的专家偏置]]：DeepSeek-V2/V3 的无辅助损失均衡策略：为每个专家维护偏置 b_i，仅在 Top-K 排序阶段使用、不进入门控权重，按近期负载动态调节，主任务梯度流完全不受干扰，兼得均衡与模型质量。
- [[细粒度专家切分与共享专家]]：DeepSeekMoE 的两项架构创新：细粒度切分把 N 个大专家拆成 mN 个小专家、激活数从 K 增至 mK，组合自由度指数级提升；共享专家隔离承接通用知识、避免路由专家重复学习共性内容。
- [[MoE显存墙与量化压缩]]：MoE 的显存墙与三条应对策略：全部专家参数必须驻留显存即便推理时大多闲置；专家并行按专家维度切多卡、QMoE 以 0.8bit 压到 160GB 以下、Sparse Upcycling 从稠密 checkpoint 复用约 50% 沉没训练成本。
- [[MoE通信开销与优化路线]]：专家并行下 token 跨卡路由引入 All-to-All 通信，未优化时可占训练时间 30%–40%；三条正交优化路线是量化压缩减传输量、通信融合藏传输时间、拓扑感知调度缩传输距离，可叠加使用。
- [[MoE推理部署与冗余专家]]：MoE 推理期的负载不均与部署优化：训练期均衡手段不保证线上分布，主流用冗余专家（DeepSeek EPLB）复制热点并重排；另有静态 Top-K 掩码代价与动态形状导致 CUDA Graph 难捕获两类隐性开销。
- [[Softmax归一化原理]]：Softmax 由四条硬约束（每项>0、总和=1、保持相对强弱、处处可导）逼成唯一自然解，指数的差分变比值让 logit 加法对应概率乘法，并导出平移不变性；公式三步即可算完。
- [[温度参数与生成采样]]：输出层 softmax 之后的三个解码旋钮：温度 T 通过 softmax(z/T) 在保守确定与随机创造间连续调节（T→0 退化 argmax、T→∞ 退化均匀），Top-k 与 Top-p 截断低质量词后再归一化采样。
- [[注意力缩放与因果掩码]]：注意力层 softmax 的两个配套设计：除以 √d_k 把点积方差拉回 1、防止 softmax 进入饱和区导致梯度消失；causal mask 给屏蔽位置加 −∞，softmax 后概率严格为 0，是「看不到未来」的数学表达。
- [[Softmax数值稳定性]]：softmax 的数值稳定手段：利用平移不变性先减去最大值使指数上界压到 e⁰=1 从而杜绝溢出，再由 online softmax 支持分块流式计算，是 FlashAttention 把显存从 O(n²) 降到 O(n) 的核心技巧。
- [[交叉熵与梯度简化]]：softmax 与交叉熵复合后的训练性质：L = −log softmax(z)_y 的梯度简化为 p − y（预测分布减真实分布），形式简洁且无饱和问题，困惑度即交叉熵的指数 PPL = e^L。
- [[Softmax变体族谱]]：Softmax 变体按控尖锐度、稀疏化、省算力三条动机分族：温度与知识蒸馏、Sparsemax 精确 0、Gumbel-Softmax 可微 one-hot、层次化 softmax 与负采样降复杂度；共性是牺牲标准版的某条性质换特定收益。
- [[Tokenizer分词编码]]：Tokenizer 将连续自然语言切分为模型词表中的最小离散单元 token，现代大模型普遍采用 BPE 或其变体（Unigram、WordPiece），切分粒度介于词与字符之间。
- [[Embedding与位置编码]]：Embedding 层将 token ID 映射为高维向量，位置编码从绝对位置演进到 RoPE（旋转位置编码），使注意力得分仅依赖 token 间的相对位置差。
- [[SwiGLU门控激活]]：SwiGLU 是现代大模型 FFN 的主流门控激活函数，以 Swish 门控替代传统 ReLU，中间维度约为隐层的 2.7 倍，FFN 参数量约占全模型的 2/3。
- [[采样解码策略]]：采样解码策略从概率分布中选出下一个 token，在确定性与多样性间权衡：Greedy 确定性输出、Temperature 连续调节、Top-K 固定候选数、Top-P 动态候选集。
- [[自回归迭代与终止]]：自回归迭代将生成的 token 追加到上下文末尾作为下一轮 Decode 输入，循环直到命中 EOS、达到 max_new_tokens 或命中自定义停止字符串。
- [[投机解码]]：投机解码在不改变输出分布的前提下加速 Decode：草稿模型起草候选、目标模型一次前向并行验证、按 min(1,q/p) 逐位接受、拒绝处重采样，将验证 K 个 token 的开销压到近似生成 1 个，实现无损加速。
- [[投机解码采样机制]]：投机解码采样机制由逐位接受（r=min(1,q/p)）、拒绝截断与拒绝处从修正分布 max(0,q-p) 重采样三部分构成，保证输出边缘分布恰为目标分布、无损由重采样保证。
- [[期望接受长度]]：投机解码单轮收益的量化刻画 E[accepted]=Σ∏p·r，由草稿与目标分布接近度决定；加速本质是摊薄权重加载，草稿长度 K 建议 4–8。
- [[草稿模型分类]]：草稿模型六类方案决定投机解码的成本、接受率与适用场景：独立草稿模型/Medusa/EAGLE/内置MTP/无模型草稿/LayerSkip/树形投机。
- [[MTP多Token预测]]：MTP（多Token预测）是训练时内置预测头的方案，目标模型自带 MTP 头推理时直接作草稿，官方即插即用、零额外部署，代表为 DeepSeek V3、腾讯混元，是 MoE 模型首选。
- [[KV Cache显存估算]]：KV Cache 显存估算公式：2 × 层数 × 序列长度 × KV 头数 × head_dim × 字节数，随序列长度线性增长、随 batch size 线性倍增，是长上下文部署的核心约束。
- [[Agent沙箱定义与安全价值]]：Agent 沙箱的定义与安全价值：以封闭工作间类比界定其约束对象是智能体自主行动而非外部恶意代码，并解释防线为何从防外部攻击转向防自身失控。
- [[隔离技术谱系]]：以「共享了什么」为统一判据，把 OS 原语、容器、gVisor、microVM、TEE 排成共享越少、强度越高、代价越高的权衡链，补足 Kata、Wasm、浏览器沙箱等其余形态。
- [[OS原语沙箱机制]]：seccomp-bpf、namespaces、cgroups、Landlock、Seatbelt 五种内核特性的分工与短板，以及本地 Agent 普遍采用的「OS原语管文件 + 用户态代理管网络」混合架构。
- [[gVisor用户态内核]]：Go 实现的 Sentry 用户态内核拦截并重新实现约 274/350 个 Linux 系统调用，不需 KVM 或裸金属，已支撑腾讯 Agentic-RL 日均数百万沙箱。
- [[Firecracker微虚拟机]]：基于 KVM 的极简 VMM 为每实例提供独立 guest 内核，约 125ms 启动、VMM 内存低于 5MiB，逃逸需连破两层，是云端不可信代码多租户执行的事实标准。
- [[容器逃逸与沙箱绕过]]：三组代表性 CVE 证明共享内核的安全天花板，DNS 外泄、元数据服务、VMM 与 jailer 缺陷则是与内核无关的三条绕过路径，配两条共性教训。
- [[沙箱四层技术栈]]：企业级 Agent 沙箱的隔离层、策略控制层、状态管理层、可观测层职责划分，附 Dify 把代码节点与命令行工作区拆成两套不可混用沙箱的部署实配。
- [[沙箱冷启动加速技术]]：预置快照 + 写时复制 CoW 克隆把 microVM 启动压到 60ms 以内、单沙箱基础内存约 5MB，配合预热池与分支式沙箱再降一个数量级。
- [[沙箱选型权衡与落地避坑]]：本地与云端是两条路线而非高低之分的判据，以及只读根目录、远端容器、Agent 自捕获异常三条被广泛相信的错误常识。
- [[大模型幻觉定义与本质]]：训练目标「预测下一个词元」的判准是语言合理性，用户诉求「正确回答」的判准是事实正确性，二者不等价即为幻觉；模型内部无 True 模块，且幻觉表征与正确回答完全同构。
- [[事实性幻觉与忠实性幻觉]]：以「和谁比错了」为基准把幻觉切成事实性（与客观世界知识冲突）与忠实性（与给定输入或上下文冲突）两类；摘要、翻译、RAG 等以源文档为锚的任务忠实性风险更突出。
- [[幻觉归因提示词与模型分诊]]：Anh-Hoang 等提出的幻觉归因分诊方法：用 Prompt Sensitivity 与 Model Variability 两个度量把幻觉判为提示词主导、模型主导、混合或未定四类，判据是改写提示词后幻觉是否消失。
- [[幻觉成因四条线]]：综合综述对数据—架构—推理全生命周期的分析，把大模型幻觉成因归纳为四条工程可操作的线：数据偏差、采样随机性、知识截止、压缩失真；四条线分属不同环节，因此没有单一银弹。
- [[温度归零不消除系统性幻觉]]：T=0 只切断采样扰动、切不断分布偏差：若分布本身把错误答案排在最高概率位，贪心解码会确定性、可复现地输出错误答案，证明温度不是治理手段。
- [[幻觉检测三条路径]]：覆盖在线、离线与流程内三种时机的幻觉检测三路径：黑盒采样一致性（SelfCheckGPT）、原子事实分解（FActScore）、生成期自校验（CoVe）；三条路径互不替代，没有一条能单独完成度量。
- [[幻觉三层治理框架]]：训练层治根、推理层止血、系统层兜底的三层治理框架：训练层调数据与目标，推理层控解码与检索，系统层做权限与拒答；层间互补，层内手段各有边界，不存在单一银弹。
- [[RAG幻觉治理边界]]：RAG 补的是知识截止（事实性），不自动解决忠实性：检索解决「没听说过」，不自动解决「答非所问」；以源文档为锚的场景仍需单独度量忠实性。
- [[RAG准确率保障体系]]：RAG 准确率保障的三层体系：架构层事前抑制（混合检索/切片/元数据/生成约束）、防护层事中拦截（幻觉检测/界面溯源/关键词校验）、兜底层事后止损（阈值拒答/人工复核/全链路日志）；核心认知是放弃 100% 准确率目标，改为把出错概率压到可接受范围。
- [[RAG绝对准确不可达]]：RAG 绝对准确率不可达：采样随机性与训练分布偏差是架构级固有属性，调参只能缓解无法根治；temperature=0 仅消除采样扰动，错误答案若在分布中已占高位，贪心解码仍会稳定输出错误。
- [[RAG阈值拒答机制]]：对检索相似度设定门槛，低于阈值直接拒答而非让模型强行生成；阈值经离线标注与线上 A/B 标定，拒答不是失败而是把不可靠输出挡在用户之外的成本控制手段。
- [[生成侧结构化约束]]：把模型视为不可信的文本处理单元，用提示词约束「仅依据上下文作答」、temperature=0 消除采样扰动、强制输出检索原文的结构化 JSON 阻断自主概括；约束的是行为边界，不是提升模型智力。
- [[RAG界面溯源设计]]：回答同步展示原文引用来源与具体内容，把信任关系从「盲信模型」转为「用户可核验」；零推理成本防线，与幻觉检测互补而非替代。
- [[领域关键词校验]]：面向医疗、法律、金融等高风险行业构建领域词库，命中时校验关键词解释与原文是否一致，防止关键信息被流畅编造；属用领域知识兜住通用检测的盲区。
- [[轨迹评估]]：评估对象维度的过程侧：关注 Agent 完整执行路径（工具调用序列、入参、中间推理、多轮状态与重试），按采集轨迹→定义合法轨迹→比对判读三步实现，可发现「结果正确但路径违规」，代价是标注成本高、多条合法路径难对齐。
- [[结果评估]]：评估对象维度的终态侧：只看最终输出或终态是否达标，核心是把任务目标转化为可机器验证的形式，三类实现为单元测试式（SWE-bench Fail-to-Pass）、终态比对式（τ-bench）、函数正确性式（HumanEval）；对「蒙对」与「违规但结果正确」完全失明。
- [[LLM-as-a-Judge]]：以强 LLM 按评估标准对候选输出打分或成对比较的裁判范式，与人类偏好一致性超过 80%，是人工评估的可扩展近似；已知位置/长度/自我增强偏差，可用交换顺序、控长度、多裁判投票缓解，本质是被动的单次文本打分器。
- [[Agent-as-a-Judge]]：用具备工具调用能力的 agentic 系统评估另一个 agentic 系统，judge agent 自主读取需求文档、检查中间产物并提供中间反馈；DevAI 基准上优于 LLM-as-a-Judge、可靠性与人工基线相当，省约 97.72% 时间与 97.64% 成本，存在「谁评估评估者」的元评估问题。
- [[人工评估与裁判校准]]：由人工按 rubric 打分或做偏好比较的评估方法，是金标准但成本极高不可扩展；核心定位是给自动化裁判提供可信度锚点（校准）并审计高风险场景，与自动化裁判构成「标注锚点→扩量→抽检复核」闭环。
- [[pass@k与pass^k]]：符号相近、语义相反的一对成功率指标：pass@k = 1 − C(n−c,k)/C(n,k) 衡量 k 次中至少一次成功（能力上限），pass^k = (c/n)^k 衡量 k 次全部成功（一致性与生产可靠性）；单次成功率 70%、k=3 时分别为 97.3% 与 34.3%。
- [[Agent评估组合策略]]：四类方法与两类指标按研发生命周期分四阶段组合：CI/CD 回归用 code-based 做硬门槛、离线深度评估用 LLM/Agent Judge 加 human 校准、基准对比跑 SWE-bench/τ-bench/AgentBench、生产监控以轨迹评估加 pass^k 为主。
- [[基准污染与动态基准]]：测试数据混入训练语料导致分数虚高、静态基准因公开饱和而失去区分度；应对分两路——检测侧用检索比对、TS-Guessing、训练数据检查与成员推断，防御侧用动态题源、程序化出题与私有测试集，代表方案 LiveBench 使头部模型准确率仍低于 70%。
- [[TS-Guessing污染检测]]：不依赖训练语料的黑盒污染检测：遮蔽多选题错误选项、只留正确答案并要求补全，命中率异常偏高即为见过该题的证据；与检索比对互补，可在闭源模型上使用，但阈值判读带主观性，需多条证据链交叉确认。
- [[LLM评委偏差与去偏差]]：LLM 评委的三类系统性偏差（位置/冗长/自我增强）与定向缓解手段：位置对调重评、长度控制胜率、多评委集成与人工锚例；判据是换评委、换顺序或控长度后排名是否大幅变动，即所测是评委偏好还是模型真实能力。
- [[长度控制胜率]]：用广义线性模型拟合带偏标注器偏好、再条件于 Δlen=0 推断反事实偏好；AlpacaEval 2.0 借此把与 Chatbot Arena 的 Spearman 相关性由 0.94 提升到 0.98，胜率归一化标准差由 25% 降至 10%；只剥离长度这一中介变量。
- [[置信度校准与ECE]]：度量自报概率与实际正确率的偏离，两大指标为 ECE 与 Brier Score、可靠性图可视化；基座模型校准良好但 RLHF 后明显退化（GPT-4 报告 ECE 0.007→0.074），过度自信使榜单无法区分高置信错误与真知。
- [[语言化置信度]]：让模型用自然语言说出把握程度，校准优于条件概率；多次采样并语言化置信度可显著恢复 RLHF 模型的校准（ECE 相对降约 50%），但效果目前仅在事实回忆类问题验证，推理与算术场景的迁移性待检验。
- [[可验证性四通道]]：证据可信不等于引用数量，完整形态含四条通道——可执行验证（单元测试/求解器/模拟环境）、程序化 ground truth、引用溯源与忠实度（仅限事实与检索，不适用数学与代码）、复现性（脚本/提示词/种子公开）。
- [[RAGAS无参考指标]]：无参考评测 RAG 的指标体系：论文核心三项为忠实度、答案相关性、上下文相关性，工具库再把上下文维度细分为上下文精度与上下文召回；忠实度衡量回答是否被检索上下文支撑，比统计引用数量更接近证据可信的实质。
- [[AI安全定义与边界]]：AI安全（AI Safety）指防范人工智能系统在开发、部署与运行全生命周期中引发事故、滥用或有害后果的跨学科领域，其中事故指模型无对手介入却因目标误设或分布偏移偏离设计意图、滥用指恶意行为者刻意利用模型能力、有害后果指部署外溢的社会系统性风险；并与关注「能否被非法侵入」的 AI 安全防护（AI Security）互为补充。
- [[机器学习安全四大类别]]：机器学习安全的技术版图可划分为鲁棒性、监控、对齐、系统安全四个相互嵌套的类别，类似安全工程中的瑞士奶酪模型——多层防御叠加阻挡单点失效；四者逻辑分工依次回答模型「想不想做坏事」「能不能被诱导做坏事」「做了能否被发现」「整个生态会不会被拖垮」。
- [[三大威胁向量]]：大语言模型部署后的三类主要攻击通道：越狱（构造输入使模型无视安全协议）、提示注入（把恶意指令混入模型可见输入流，覆盖或篡改系统提示）、内容安全（正常或对抗输入下生成违规有害内容）；越狱本质是提示注入的特例，三者常叠加于同一攻击链。
- [[越狱攻击]]：越狱（Jailbreak）指以精心构造的输入使大语言模型完全无视自身安全协议、绕过拒绝策略的对抗攻击，是提示注入的特例；典型手段有角色扮演、多轮诱导与 GCG 梯度搜索后缀，防御方向为拒绝方向强化与分类器防御（如 Constitutional Classifiers）。
- [[红队测试四步闭环]]：红队测试不是一次性事件，而是嵌入 AI 开发生命周期的持续对抗循环，可拆解为发现（威胁建模与攻击面枚举）、清单（结构化攻击用例库）、迭代（自动化与多轮攻击）、报告（量化评分与修复建议）四个阶段，并以修复后回归与新攻击手法涌现两条回路闭环。
- [[红队量化指标ASR与URR]]：红队测试的核心量化指标：攻击成功率 ASR、过度拒绝率 URR、毒性生成率 TGR、失败检测率 DFR，用于把模型风险变成可比可回归的数字；工程实践三要点为多基准报告而非单点数字、ASR 与 URR 的权衡、判官自身可靠性。
- [[红队测试边界与军备竞赛]]：红队测试量化结论的固有边界：通过红队不等于绝对安全（未发现漏洞只是采样式搜索未命中）、攻防是持续军备竞赛（自动化攻击可跨模型迁移，结论会随攻击演进失效）、防御存在量化成本（提升鲁棒性往往带来过度拒绝等代价），因此红队的真实定位是把风险降到可量化可接受阈值的持续工程过程。
- [[GCG对抗攻击]]：GCG（Greedy Coordinate Gradient，贪心坐标梯度搜索）是一种自动化对抗攻击：通过梯度引导的逐 token 搜索生成可迁移的对抗后缀，使对齐模型输出有害内容，且攻击结果可从开源模型迁移到 ChatGPT、Claude 等黑盒模型，是红队迭代阶段的代表性技术。
- [[文档智能]]：文档智能 = 把非结构化文档转成机器可理解、可校验、可驱动动作的结构化数据的四段能力链（解析→理解→校验→驱动），而非 OCR 精度升级；五层能力阶梯从 L0 字符层到 L4 业务层，OCR 从"产品"降级为"组件"。
- [[OCR文档解析]]：OCR 的四段式流水线（预处理/文本检测/字符识别/后处理）与六条无法靠调参解决的结构性局限，源于输出形态是"文本流"、丢失二维空间关系与业务语义；清晰印刷体 CER 可低于 1%、手写体 3-5%。
- [[版面分析]]：决定文档元素按什么顺序拼接，最易被低估；五个核心任务中阅读顺序最难（视觉无显式标注靠推断），传统坐标排序 vs VLM 语义推断各有短板。
- [[表格结构还原]]：表格二维结构无法用序列表达，四阶段（区域检测→结构→内容→还原）；无线表最难，TableFormer 直接预测结构切断 OCR 级联、两阶段解耦避免内容误差污染。
- [[公式识别]]：把二维数学结构序列化为 LaTeX/MathML，难点随复杂度非线性上升；评测用 CDM（Character Detection Matching）而非编辑距离，因为它衡量"公式是否视觉正确"。
- [[文档VLM三大范式]]：文档解析架构三选一——传统流水线（可解释但误差级联）、端到端 VLM（语义强但幻觉/O(N²)）、解耦式多阶段（全局版面+局部精细识别、兼顾精度效率抑幻觉）；端到端有 token 冗余、幻觉、分辨率三碍。
- [[文档智能校验三支柱]]：可校验是文档智能区别于普通 OCR 的核心：置信度、溯源、规则三支柱；落地走五步法（采集→分类→提取→审核→录入），审核环节不能省，兜底闭环"抽取—规则校验—转人工"。
- [[文档精度评估三层]]：文档智能离线精度分三层指标：字符层（CER/WER）、结构层（TEDS/CDM/mAP）、语义层（字段F1/STP）；四陷阱是基准≠业务、字符掩盖字段、单一指标失真、静态基准饱和。
- [[文档智能能力边界]]：六条能力边界：字符准≠业务对、多模态不是银弹、审核环节不能省、绝对准确不可达、模型上限由数据决定、文档是 Agent 的感官——边界是设计约束而非缺陷。
- [[正则化]]：在训练目标中加入约束或惩罚、限制模型复杂度以提升泛化能力的技术：以少许偏差为代价压低有效复杂度、换取方差大降，让模型学通用规律而非死记噪声。
- [[过拟合]]：模型在训练集表现好、陌生数据大幅退化的现象，源于参数过多+数据太少+噪声偏大叠加时模型死记训练样本；泛化误差分解为偏差²+方差+噪声，正则化主攻降方差。
- [[偏差-方差权衡]]：泛化误差 = 偏差² + 方差 + 噪声；过拟合模型偏差极低而方差极高，正则化的主攻方向是降低方差、代价是偏差略升。
- [[L1正则与LASSO]]：L1 正则（Lasso）以绝对值之和作惩罚、把权重推到精确零产生稀疏解并附带特征选择；几何上对应菱形约束，交点大概率落在坐标轴尖角上。
- [[L2正则与权重衰减]]：L2 正则（岭回归/权重衰减）以平方和作惩罚、把权重均匀缩小但趋于平滑不归零；几何上对应球面约束，SGD 下 L2≡权重衰减。
- [[弹性网络]]：L1+L2 组合正则（λ1‖w‖₁+λ2‖w‖₂²），兼得稀疏选择与相关特征下的稳定性，具组效应——高度相关变量倾向于同进同出。
- [[Dropout]]：训练时按概率随机置零单元输出的结构干预正则，打破神经元间共适应、等效隐式集成平均；Srivastava 2014 提出。
- [[提前停止EarlyStopping]]：监控验证集误差一回升即停止训练并回滚最优参数的简单正则，等价于隐式限制参数搜索范围。
- [[批量归一化与正则化]]：Batch Norm 主要稳定各层输入分布、加速训练，因 mini-batch 统计量引入随机性而附带轻微正则效果，其强度随 batch 增大而减弱。
- [[数据增强与噪声注入]]：从源头降方差的正则路线——数据增强、噪声注入、合成更多数据扩充有效样本量、稀释噪声记忆，对应过拟合「数据太少」诱因。
- [[贝叶斯与优化视角正则化]]：三重视角——频率学派视正则化为参数空间显式约束；贝叶斯视角下正则项对应先验对数（L2↔高斯、L1↔拉普拉斯）；优化视角下正则把优化引向更平坦极小值。
- [[AdamW与权重衰减解耦]]：SGD 下「权重衰减≡L2」在 Adam 自适应学习率下失效、L2 惩罚被削弱；AdamW 将权重衰减从梯度自适应机制解耦，多项实验改善泛化。
- [[Agent生产化四类痛点]]：Agent 生产化的四类核心痛点：LLM 本身不可靠（非确定性/幻觉/提示注入）、脚手架差异导致同一模型表现不同、越权与不可逆操作风险（OWASP Excessive Agency）、成本失控与无界循环；共同指向需要外部可靠性约束体系。
- [[Harness循环五阶段]]：Harness 循环五阶段：Perceive→Reason→Plan→Act→Observe，循环往复直至命中终止条件；每阶段有职责、失败模式与工程护栏。
- [[Agent幂等四层防御]]：Agent 幂等设计：调用方是 LLM 而非确定性客户端、幂等键需从稳定结构上下文派生（run_id+step_id+tool_name）；L1-L4 多层防御 + 幂等键三条铁律，重试时避免重复执行副作用。
- [[Agent终止条件多路熔断]]：Agent 不应仅靠模型自判任务完成：生产级终止需至少五路熔断（目标达成/步数上限/时间上限/预算上限/无进展检测），命中安全停止时返回最佳答案而非悬挂或静默截断。
- [[Agent成本四维预算]]：Agent 成本管理的四维预算：token、步数、时间、金额，统一为 middleware 挂在 Act 层之前；金额超阈值走熔断而非仅告警。
- [[四档沙箱隔离模型]]：Agent 沙箱四档隔离模型：T1 Wasm 无环境权限→T2 容器共享内核→T3 硬化容器/gVisor 用户态内核→T4 microVM 独立内核；生产级需纵深防御。
- [[Agent最小权利与审批门]]：Agent 权限控制两维模型：操作可逆性（可逆/难逆/不可逆）× 爆炸半径（窄/宽/全系统），交叉界定四档授权门槛；不可逆或高影响操作强制人工审批。
- [[Agent可观测追踪三轴]]：Agent 可观测性三轴：执行轴（token/step 可直接观测）、成本轴（按账号/会话聚合+实时看板）、审计轴（不可重建、受合规约束）；健康信号供编排反馈。
- [[Checkpoint与DurableExecution差异]]：运维层状态恢复两种范式：Checkpoint（记录快照）vs Durable Execution（时间旅行重放）；Agent 长时运行应显式标记 durable 边界并组合不可变事件日志与外部幂等键。
- [[具身Agent与环境接地]]：Agent AI 把智能体定义为能感知视觉刺激、语言输入与环境接地数据并产出有意义的具身动作的交互系统；本页梳理从多模态智能体到具身智能体的定义谱系、动作型与交互型的二分，以及「环境接地」为何是它与软件工具型 Agent 的分水岭。
- [[AgentToken与下一动作预测]]：Agent Transformer 在视觉 token 与语言 token 之外引入第三类 agent token，为具身动作预留输入输出子空间，并以『下一具身动作预测』作为统一训练目标；本页解析 agent token 的设计动机、相对冻结 LLM 方案的四项优势，以及它与工具调用的本质差异。
- [[环境接地式幻觉治理]]：环境接地式幻觉治理：只依赖预训练模型的智能体把内部知识当世界状态，动作因此在部署环境里落空；本页解析这条与数据偏差/采样随机/知识截止/压缩失真平行的第五条成因，以及在『系住内部知识』这一类手段中的位置与边界。
- [[Agent训练方法阶梯]]：Agent 能力从哪来的三级阶梯：零样本/少样本的 Agent 模块与基础设施、预训练微调级的 agentic 基础模型、以及在环境交互中持续自我改进；本页解析每级的适用前提、模仿学习相对强化学习的取舍理由，以及『无限记忆智能体』这一关键设计。
- [[协作效率指标CoS]]：CoS（Collaboration Score，协作效率分）是 CuisineWorld 多智能体协作基准的自动化指标，用来自动量化多智能体在协作任务上的配合效率；本页解析它的设计意图、集中调度与去中心两种模式、以及多智能体系统缺少『协作质量』标尺这一空白。
- [[联邦学习]]：联邦学习是多个持有本地数据的客户端在服务方协调下协作求解同一模型的分布式范式，原始数据不出域，仅交换模型参数或梯度；本页给出术语界定、与分布式学习的范式分野、系统成立的四项约束，以及横向/纵向/迁移三类划分。
- [[FedAvg联邦平均]]：FedAvg 是联邦学习最基础的聚合算法，按客户端样本量加权平均本地更新，并以本地多步训练换取通信轮次下降；本页给出加权聚合公式、单轮四步流程，以及「核心贡献是通信效率而非精度」这一常被忽略的设计出发点。
- [[FedProx近端优化]]：FedProx 针对联邦学习的系统异构与统计异构双重难题：允许客户端完成可变本地工作量以缓解掉队者，并在本地目标上加入近端项把模型约束在全局模型邻域；实测在高度异构下收敛更稳，平均绝对测试精度提升约 22%。
- [[安全聚合SecAgg]]：安全聚合（SecAgg）通过多方密码学协议让服务器只能得到所有更新的总和、无法查看任何单个客户端的更新，解决联邦学习中「服务器不可信」的问题；本页给出其安全模型、掉线容忍能力与实测通信开销（1024 用户 1.73 倍膨胀）。
- [[差分隐私]]：差分隐私在联邦学习中用于解决「聚合结果可被推断」的威胁：通过注入校准噪声使单个样本的存在与否在统计上不可分辨；本页对比中央差分隐私与本地差分隐私的信任假设与精度代价，并说明其与安全聚合、TEE 的分工。
- [[梯度泄露攻击]]：梯度也会泄露数据：NIPS 2019 的深度梯度泄露（DLG）证明仅凭共享梯度即可重建训练数据，由此推翻「不上传数据即安全」的假设；本页梳理成员推断、属性推断、模型反演三类攻击的目标与量化效果，并说明它们对联邦学习防护设计的约束。
- [[递归自我改进RSI]]：递归自我改进（RSI）指系统把研发本身作为改进对象，使改进机制进入改进对象集合、能力跨代复利累积；本页给出术语定义与 Yampolskiy 形式化判据 f_{n+1}=Φ(f_n,f_n)，并划清它与自我改进、自我对弈、AutoML、反思式方法的层级边界。
- [[RSI四项判定标准]]：严格递归自我改进须同时满足持久性、自主闭环、递归增益、稳健可控四项标准；本页逐条拆解每项的工程验证方式，并给出缺第三条即降级为有界 RSI 的判定规则，是区分「真 RSI」与「看起来像 RSI」的实操清单。
- [[有界RSI与开放式RSI]]：有界 RSI 与开放式 RSI 的分界在于改进能否复利：只满足持久性与自主闭环而不满足递归增益的系统属有界 RSI，产出线性加速；四条齐备才是开放式，理论上指数增长；本页用已观测收益对照说明二者不可混为一谈。
- [[点火条件与复利因子G]]：点火条件与复利因子 G=∏εᵢ：把 AI 进展建模为有向图，各反馈环弹性之积大于 1 时进入自我维持加速（点火）态，小于 1 时逐轮衰减；本页解释弹性的定义、G 与智能爆炸 (1+ε)^n 的关系，以及为什么这一阈值是有界与开放式的分界线。
- [[哥德尔机]]：哥德尔机（Gödel Machine）是 Schmidhuber 2003 年提出的 RSI 首个数学严格框架：持有证明搜索器与效用函数，仅当在形式公理系统内证明改写使效用严格更优时才执行改写，因而所得改写全局最优、无局部极值；本页解析其形式、局限与向工程路线的转向。
- [[System One 模型]]：借用卡尼曼双系统「系统一」的一类 AI 模型形态：输入状态+预定义问题，输出带校准概率的类型化决策，不生成文本；首个落地实例是 TypeSafe AI 的 Jev，与生成式 LLM（系统二）形成分工互补而非替代。
- [[类型化输出]]：System One 模型（如 Jev）的核心机制：答案约束在预定义 schema 内、不写自由文本，结构化错误率 0%；注意「零幻觉」是厂商口径，仅指结构不出格、不表示语义正确。
- [[并行采样机制]]：Jev 毫秒级响应的根本：所有答案一次前向计算并行产生，非 LLM 逐 token 自回归；一次调用多个不同类型问题共享输入、独立并行评估。
- [[校准置信度]]：每个决策带一个校准过的概率，让软件判断自动执行还是升级人工复核，是把不可靠输出挡在自动化流水线之外的可信接口基础。
- [[决策原语]]：System One 模型对「机器判断」的最小抽象：Choice（选一个）/ Score（打分）/ Boolean-Noul（陈述是否成立）三种原语通过同一接口混用、一次调用并行评估。
