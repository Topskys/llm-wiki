# MinerU

## 简介

MinerU 是上海人工智能实验室、OpenDataLab 开源的高精度文档解析引擎。在 2.5 版本从"模块化流水线"转向"解耦式 VLM"，核心是解决文档解析端到端方案的三难，聚焦高精度解析复杂版面、公式与表格。

- 出身上下文：[[文档智能工程落地]] 中两条工程路线之一（另一条为 [[Docling]]）
- 定位：以最高解析精度为目标的解析引擎，输出 Markdown、JSON（带 bbox）

## 发展脉络：从流水线到解耦式 VLM

早期方案用 PDF-Extract-Kit 编排版面检测、公式识别、表格抽取等**专用模型**（即 [[文档VLM三大范式]] 的传统流水线路线）。优点是可对单组件独立优化，缺点明显：

- 误差在阶段间传播（检测错则后续必错，见 [[OCR文档解析]] 的误差级联）
- 多栏、跨页版面的鲁棒性有限
- 模块彼此依赖，维护繁琐

MinerU 2.5 因此转向**解耦式多阶段**范式：把全局版面分析与局部内容识别拆开，让高分辨率只作用于需要精细识别的局部。

## MinerU 2.5 架构

### 两阶段解析策略

```mermaid
flowchart LR
    A["原始文档图像"] --> B["Stage I 版面分析<br/>整页缩放 1036×1036<br/>固定尺寸 → bbox 更稳"]
    B --> C["按版面裁剪<br/>局部区域"]
    C --> D["Stage II 内容识别<br/>原生分辨率 上限 2048×28×28<br/>保住密集文本与公式细节"]
    D --> E["文本 · 公式 · 表格<br/>结构化输出"]
    style B fill:#E9F4F5,stroke:#117C88
    style D fill:#E9F4F5,stroke:#117C88
    style E fill:#117C88,color:#fff,stroke:#0A5A63
```

- **Stage I**：整页缩放至 1036×1036，固定尺寸换取更稳定 bbox 与更高训练效率，低成本获得全局结构（对应 [[版面分析]]）。
- **Stage II**：按版面裁原图局部、原生分辨率输入，上限 2048×28×28，兼顾细节与算力（对应 [[OCR文档解析]] 的识别 / [[表格结构还原]] / [[公式识别]] 的精细识别）。

### 架构三件套

| 组件 | 规格 | 作用 |
|---|---|---|
| 语言模型 | 0.5B Qwen2-Instruct | 解析任务对 LLM 依赖低；1D-RoPE 换 M-RoPE 适配裁剪块多分辨率 |
| 视觉编码器 | 675M NaViT（Qwen2-VL 初始化） | 支持动态分辨率与 2D-RoPE |
| Patch Merger | 2×2 视觉 token pixel-unshuffle | 折中效率与性能 |

### 训练三阶段

1. **Stage 0 模态对齐**：先只训 Patch Merger 两层 MLP 并冻结其余，再全解冻做视觉指令微调
2. **Stage 1 解析预训练**
3. **Stage 2 解析微调**

配数据引擎生成训练语料。

## 收益

复合收益辐射多个维度：算力降一个数量级、可解释性提升、幻觉被结构性抑制、两阶段可独立迭代。MinerU 2.5 把复杂长公式与中英混排公式的准确解析列为核心改进，也与"[[文档智能能力边界]] 中多模态不是银弹"形成互补——端到端有 token 冗余、幻觉、分辨率三碍（见 [[文档VLM三大范式]]），解耦是解法。
