# 主流LLM网关方案对比

## 对比总览

| 维度 | LiteLLM | Portkey | APISIX-AI | FrugalGPT | 本文双层网关 |
|------|---------|---------|-----------|-----------|--------------|
| 定位 | 开源 LLM 网关 | AI Gateway | APISIX 网关 AI 插件 | 成本优化路由 | 双层网关+流量治理 |
| 多模型路由 | 基础 | 支持 | 流量转发为主 | 模型选择 | 动态（同Key/异构降级） |
| RPM+TPM 联合配额 | 无 | 弱 | 无 | 无 | 两级令牌桶+预扣退款 |
| 配额超发治理 | 无 | 无 | 无 | 无 | Redis 分布式桶防超发 |
| SSE 专属容错 | 无 | 无 | 无 | 无 | 已流式中断不重试 |
| 能力标签约束降级 | 静态映射 | 静态配置 | 无 | 提示压缩+选模型 | 硬/软标签筛选+校验 |
| 熔断状态机 | 基础 | 有 | 无 | 无 | 5xx 驱动三态+灰度回切 |
| 灰度回切 | 无 | 无 | 无 | 无 | 渐进放量观测 |
| Agent 工具降级保护 | 无 | 无 | 无 | 无 | allow_fallback 开关 |

## 核心结论

- **共性短板**：市面方案对 __RPM/TPM 双配额建模粗糙__（缺预估扣减+退款周期）、__SSE 容错逻辑简陋__（重试导致输出重复/语义错乱）、__异构降级多用硬编码映射__（无能力校验，Agent 工具调用易降级到不支持 Function Call 的模型）。
- 本文靠 **双通道（5xx 熔断 vs 429 配额）+ 多环闭环（降级→灰度回切）** 差异化补齐这三块短板。
- FrugalGPT 与本文不在同一层：它做成本视角的提示压缩/模型选择，不解决上游 429 流量治理，可与之**共存叠加**而非替代。

## 要点拆解

### LiteLLM
提供多模型路由、重试与 fallback，是当前事实标准组件，但吞吐模型简单、无 TPM 联合管控、SSE 容错弱。

### Portkey
支持降级、缓存、可观测性；降级为静态配置，缺能力标签筛选。

### APISIX-AI
在边缘网关（APISIX）内集成 LLM 路由，偏重流量转发，缺独立熔断状态机与灰度机制。

### FrugalGPT
成本优先路由，通过提示压缩与选模型控成本；不处理 429/限流，与网关容错能力互补。

### 本文方案差异化归纳
三层叠加：①配额层（两级令牌桶+预扣退款）②容错层（5xx 熔断 | 429 配额双通道）③恢复层（灰度回切+重试预算）。三者闭环覆盖「限流→隔离→恢复」全生命周期。
