# MoE与稠密模型对比

## 七维对比

| 维度 | 稠密模型 | MoE 模型 |
|---|---|---|
| 激活参数 | 全量激活 | 仅 Top-K（~5%–30%） |
| 知识容量 | = 激活量，受算力限制 | 可远超算力预算 |
| 单 token FLOPs | 与总参数成正比 | 与激活参数成正比 |
| 训练难度 | 低，稳定 | 高（均衡/坍缩/调参） |
| 显存需求 | 一份参数 | 全部专家驻留 |
| 推理效率 | 单 batch 利用率高 | 需大 batch + 专家调度 |
| 规模收益 | 成本线性上升 | 规模越大越划算 |

## 核心结论

**规模越大，MoE 的「容量/算力比」优势越显著**；数 B 以内的小规模场景，稠密模型在稳定性与部署简易性上仍占优。

逐行读法：

- **前四行是收益**：激活比例 5%–30% 意味着同样算力下可以养更大的模型（见 [[稀疏激活与容量解耦]] 的参数对比表）。
- **中间三行是代价**：训练要额外处理 [[路由坍缩与赢家通吃|坍缩与均衡]]，显存要按总参数算（[[MoE显存墙与量化压缩]]），推理要靠大 batch 与专家调度（[[MoE推理部署与冗余专家]]）。
- **最后一行是选型判据**：稠密成本线性上升，MoE 的固定开销（专家池、通信、调度）随规模被摊薄。

## 选型建议

| 场景 | 建议 | 理由 |
|---|---|---|
| 数十 B 以上、追求性价比 | MoE | 容量/算力比优势显著，已是前沿主流选择 |
| 数 B 以内、强调部署简洁 | 稠密 | 训练稳定、单 batch 利用率高、无均衡调参 |
| 已有稠密 checkpoint 想扩容量 | MoE + Sparse Upcycling | 复用约 50% 沉没训练成本，优于从零训练 |
| 单机小卡、显存紧张 | 视量化而定 | QMoE 可把 1.6T 压到 160GB 以下，但需接受量化校准成本 |
