# 主流分词方案对比

## 核心结论

三条子词算法走的是三种准则，殊途同归解决词表爆炸 [[1]](#ref-1)[[2]](#ref-2)[[3]](#ref-3)；SentencePiece 则把算法封装成工程框架 [[4]](#ref-4)。算法层选准则，工具层选实现与生态，两层分开看。

## 要点拆解

### 算法层对比（BPE / WordPiece / Unigram / SentencePiece）

| 算法 | 合并或删减准则 | 词内标记 | 代表用户 |
|---|---|---|---|
| BPE | 最高频相邻对迭代合并 | 无（字节级变体） | GPT 系列、Llama |
| WordPiece | 似然增益最大 | ## 前缀 | BERT、DistilBERT |
| Unigram | 迭代删除似然损失最小项 | 无 | T5、ALBERT |
| SentencePiece | 框架，封装 BPE 与 Unigram | ▁ 表示空格 | T5、Llama、多语言模型 |

- BPE 与 WordPiece 是「往上合并」，Unigram 是「往下删减」；
- SentencePiece 处在框架层，不与前三者并列竞争，而是封装它们。

### 工具层三件套

| 工具 | 实现与定位 |
|---|---|
| HuggingFace Tokenizers | Rust 实现，训练与编码都快，HF 生态默认 |
| SentencePiece | 语言无关框架，空格记 ▁，训练与编码一体 |
| tiktoken | OpenAI 出品 [[6]](#ref-6)，面向 OpenAI 模型的快速 BPE 编码器，按 o 系词表（cl100k / o200k） |

### 选型要点

- 训自有模型词表 → 走 SentencePiece（语言无关）或 HF Tokenizers（生态对齐）；
- 调 OpenAI API / 精确估算计费 → 走 tiktoken；
- 复现 BERT 体系 → WordPiece。
