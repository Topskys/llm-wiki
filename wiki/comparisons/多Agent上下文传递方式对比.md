# 多Agent上下文传递方式对比

## 核心结论

多 Agent 之间"怎么把上下文交给下一步"是路由的核心。三种方式：**上下文继承**（省事但 Token 指数膨胀）、**上下文注入**（精炼高效但易丢细节）、**Memory ID 引用**（不占窗口但引入检索成本）。没有银弹，按 token 预算与细节保真度取舍，可组合：注入摘要 + 关键细节引用。

## 对比矩阵

| 维度 | 上下文继承 | 上下文注入 | Memory ID 引用 |
|---|---|---|---|
| 机制 | 完整上下文原样复制给下个 Agent | 传递精炼后的关键内容（摘要/指令） | 传递记忆 ID，需要时从向量库按 ID 检索 |
| Token 开销 | 指数级膨胀 | 低（仅摘要） | 窗口外，几乎为零 |
| 细节保真 | 最高（无损） | 摘要易丢细节 | 按需取回、可逆 |
| 连续性 | 最好 | 依赖摘要质量 | 依赖 ID 索引与存储器 |
| 实现复杂度 | 最低 | 中（需摘要层） | 最高（需向量库/记忆系统） |
| 适用场景 | 短链、低并发、保真优先 | 长链、Token 敏感 | 长历史回溯、跨会话复用 |

## 决策树

| 你的约束 | 推荐 |
|---|---|
| Token 极度紧张 | Memory ID 引用（若已有向量库）；否则上下文注入 |
| 步骤间强依赖细节 | 注入摘要 + 关键细节以引用占位 |
| 链路短且单次 | 上下文继承（简单直接，注意量级） |
| 需跨会话复用 | Memory ID 引用 + 外部持久化 |

## 深度对比：继承 vs 引用

- **继承**：Agent A 完整上下文 → B，B 又 → C，token 指数增长，最终无人读完——这是 [[上下文污染]] 中"上下文爆炸"的直接来源，属"简单但昂贵"。
- **引用**：只传 ID + 描述，B 需要时检索原文（对应 [[上下文爆炸治理方案对比]] 的"可逆性"底座），代价是多一跳检索与索引维护，属"复杂但可伸缩"。
