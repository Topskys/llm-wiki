# 四大项目架构对比

## 核心结论
- 四个项目解决**不同问题**但共享统一架构逻辑：[[DataBus]] 是数据底座（离线 T+1 ETL），[[ModelForge-AI]] 是模型与检索工厂（训练+检索双流水线），[[LiveClip-AI]] 与 [[MultiVis-AI]] 分别做直播内容/自媒体内容生产。
- 状态存储都用 PostgreSQL，但粒度不同：DataBus 是 ETL 批调度，LiveClip 是任务级状态机，MultiVis 是 Graph 节点级 Checkpointer。

## 对比表

| 维度 | [[DataBus]] | [[ModelForge-AI]] | [[LiveClip-AI]] | [[MultiVis-AI]] |
|------|------------|-------------------|-----------------|-----------------|
| **核心问题** | 数据脏、多源异构 | 通用模型不懂商城 | 长直播剪片慢 | 种草内容批量产 |
| **架构形态** | ETL 五层流水线 | 训练+检索双流水线 | 前端 wasm + 后端 PG 队列 | LangGraph 多 SubGraph |
| **状态存储** | PostgreSQL raw/staging | 训练 checkpoint + Milvus | PG 任务表（整任务状态机） | PG Checkpointer（节点级 state） |
| **长任务处理** | 批处理 ETL 调度 | 云端训练 Job | pending→running 串行抢占 | 节点级 checkpoint 重试 |
| **实时性** | 离线 T+1 | 在线 API | SSE 进度推送 | SSE 文案流式 |
| **产出物** | SFT/RAG 数据集 | 微调模型+检索 API | 高光短视频+ASR 文本 | 图文素材包 |
| **灵购关系** | **上游供数** | **上游供模型+Rerank** | **间接丰富**（ASR/标签回流） | **下游素材供给**（多模态） |

## 拷打速答

- **「五个项目你怎么分工？」**：主负责灵购 AI RTC+回调+RAG 接入；DataBus/ModelForge 深度消费与联调；LiveClip/MultiVis 同矩阵 Agent，熟悉架构与数据回流。
- **「数据经过哪些系统？」**：用户语音 → RTC ASR → 灵购回调 → ModelForge 检索 API（Milvus Top20→Rerank Top5）→ 微调 LLM SSE → RTC TTS；知识来自 DataBus。
- **「LiveClip ASR 怎么变成灵购能用的知识？」**：ASR+高光标签 → 回流 DataBus → 9 级过滤+脱敏+抽检 → chunk+embedding → Milvus → 灵购可召回。
