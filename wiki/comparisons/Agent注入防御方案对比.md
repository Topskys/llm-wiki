# Agent注入防御方案对比

## 核心结论

- **防御范式分三层**：输入侧治理（防已知攻击）、架构隔离（从根切断）、执行层动态验证（兜底污染后上下文）。三者互补，**单一方案都不可靠**。
- 效果排序（研究基准上的 ASR 数字，仅供参考）：CaMeL 外部攻击 0 成功 > MELON-Aug 0.32% > Task Shield 2.07% > DRIFT 1.3%。
- 选择逻辑：高安全 + 结构化作数据 → 架构隔离；通用 Agent + 高交互 → 执行层验证；预算/延迟敏感 → 输入侧治理兜底。

## 三类方案关键词对比

| 维度 | 输入侧治理 | 架构隔离 | 执行层动态验证 |
|---|---|---|---|
| 代表 | 清洗管道、Prompt-Guard-2、恶意指令向量库 | 双LLM、CaMeL | Task Shield、DRIFT、MELON |
| 防注入黄金线 | 已知模式/变体 | 未知攻击（失败则降级） | 动作级任务对齐 |
| 攻击面削减 | 中（可绕过编码混淆） | 强（程序边界封闭） | 强（动作得到验证） |
| 实时成本 | 低（正则/FAISS） | 高（双模型推理） | 中（每步验证LLM调用） |
| 变形抗性 | 弱—中（靠向量语义召回） | 强（形式化约束） | 中（需识别得出冲突） |
| 局限 | 无法防 zero-day 家族 | 绑定数据提取场景 | 验证器可能被劫持 |
| 互补点 | 兜底一切 | 从根源削减爆点 | 兜底上下文污染 |

## 三套执行层方案对比

| 维度 | Task Shield (ACL 2025) | DRIFT (NeurIPS 2025) | MELON (ICML 2025) |
|---|---|---|---|
| 核心机制 | 任务-自身指令匹配，丢弃冲突路径 | 安全规划器+动态验证器+注入隔离器 | 恶意数据改写+任务对齐检测 |
| 效果（ASR） | 2.07%（GPT-4o）| 30.7%→1.3%（GPT-4o-mini）| 0.32%（MELON-Aug）|
| 效用/可用性 | 69.79% | 保持合理（多组件） | 双检测提升 |
| 侧重点 | 防直调工具被注入劫持 | 复杂任务分步安全规划 | 破坏注入载荷本身 |
| 局限 | 需任务/指令可匹配 | 验证器本身有被劫持风险 | 改写可能误伤任务数据 |

## 选择建议

- **数据密集结构化**（RAG/文档 Agents）：优先双 LLM / CaMeL，从根杜绝数据注入进入上下文。
- **高自主度工具型 Agent**（MCP 多工具）：优先 Task Shield / DRIFT 逐动作验证 + 零信任工具管控 + Fail Closed。
- **成本敏感 / 面向 C 端**：输入侧清洗 + Prompt-Guard-2 + 向量库 + 输出验证兜底，接受部分绕过风险。
- **组合优先级建议**：架构隔离 > 执行层验证 > 输入侧治理；且**必须**叠加[[LLM权限最小化]]与人工审批。
