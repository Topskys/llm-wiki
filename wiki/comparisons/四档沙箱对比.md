# 四档沙箱对比

## 核心结论

- 四档沙箱随隔离强度递进，**信任边界（是否共享宿主内核）是核心分水岭**。
- 容器共享内核仅适合受信代码；硬化容器/gVisor 用用户态内核拦截 syscall；microVM 独立内核、隔离最强。

## 横向对比

| 档位 | 隔离技术 | 信任边界 | 适用场景 | 典型工具 |
|---|---|---|---|---|
| T1 Wasm | 无 ambient authority，import 声明授权 | 无宿主能力 | 单 purpose 工具、MCP server | Wasmtime / WAMR |
| T2 容器 | namespace + cgroup | 共享宿主内核 | 受信代码、代码库内 Agent | Docker / Podman |
| T3 硬化容器 / gVisor | 用户态内核拦截 syscall | 仍共享内核边界 | LLM 生成的不完全可信代码 | gVisor / gVisor k8s |
| T4 microVM | 独立 guest 内核 | 完全独立 | 开放式 coding agent、任意 shell | Firecracker / Kata |

## 生产建议

- 纵深防御：隔离边界 + 资源限制 + 网络控制 + 权限范围 + 监控（见 [[四档沙箱隔离模型]]）。
- 信任模型决定选档：值不值得为更可信任务上 microVM，取决于 blast radius 与安全要求。
