# 知识管理方式对比：笔记 / RAG / LLM-Wiki

## 核心结论
- 传统笔记：知识零散不成体系，检索依赖关键词匹配，无法形成关联网络。
- 普通 RAG：每次提问**临时切割**原始文档，知识始终停留在素材状态，无预编译与沉淀。
- LLM-Wiki：素材入库时**一次性编译**为原子化、关联化的 [[编译型知识库]]，具备完整治理闭环。

## 要点拆解

| 维度 | 传统个人笔记 | 普通 RAG | [[LLM-Wiki框架|LLM-Wiki]] |
|---|---|---|---|
| 知识形态 | 零散碎片、不成体系 | 留在素材状态，非结构化切割 | 原子化、关联化知识网络 |
| 检索方式 | 关键词匹配，无关联导航 | 临时切块检索原文档 | 索引 + 双链 + 元数据快速定位 |
| 知识沉淀 | 无编译机制 | 无（问答后不留痕） | Ingest 预编译 + Query 回写沉淀 |
| 可追溯性 | 弱 | 弱（切块即用即弃） | source 溯源 + Git/shturl 双重留痕 |
| 治理能力 | 无 | 无 | Lint 巡检、防膨胀闸门、月度治理 |
| 最大风险 | 散、乱、不可检索 | 重复劳动、知识不沉淀 | 沦为 [[结构化垃圾场]]（有制度对抗） |

- 三者的取舍本质：投入固定维护成本（每周约 30 分钟 + 月度约 1 小时），换取检索复用效率与长期复利资产。
