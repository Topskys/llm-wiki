## 标准 Function Tool 示例

适用：原生大模型 function call，原子工具，只做一件事，无复杂业务编排，编排交给 Skill。

```python
from pydantic import BaseModel, Field

# 1. 定义入参模型（自动生成JSON Schema，大模型用来生成tool_call）
class QueryWeatherInput(BaseModel):
    city: str = Field(description="城市中文名，例如：深圳")
    unit: str = Field(default="c", description="温度单位，c=摄氏度，f=华氏度")

# 2. 原子业务执行函数
def query_weather(city: str, unit: str = "c") -> dict:
    """查询城市实时天气"""
    mock_data = {
        "city": city,
        "temp": "27℃",
        "condition": "多云",
        "humidity": "65%"
    }
    return {
        "success": True,
        "data": mock_data,
        "msg": "查询成功"
    }

# 3. 包装成Agent可用的Tool定义
weather_tool = {
    "name": "query_weather",
    "description": "获取指定城市实时天气信息，支持摄氏度/华氏度",
    "parameters": QueryWeatherInput.model_json_schema()
}

# 调用入口，LangGraph常用包装
def weather_tool_handler(raw_args: dict):
    validated = QueryWeatherInput(**raw_args)
    return query_weather(city=validated.city, unit=validated.unit)
```

### 关键要点
- **单一职责**：只做查询天气，不带循环、不带多步骤判断（多步骤交给 Skill）
- **入参用 Pydantic 做校验**，防止非法参数
- **返回统一结构**：success + data + msg，方便上层 Skill 做分支判断
- **description 写清楚**，LLM 靠这个理解什么时候调用

## MCP Tool 完整示例

MCP = Model Context Protocol，服务端对外暴露 tool，任意 MCP Client（Agent/Claude Code）都能自动发现调用。

```python
# mcp_server_weather.py
from mcp.server import Server
from mcp.types import Tool, TextContent
import json

# 初始化MCP Server
app = Server("weather-mcp-server")

# 注册MCP Tool：查询天气
@app.tool()
async def query_weather(city: str, unit: str = "c") -> str:
    """
    获取指定城市实时天气
    Args:
        city: 城市中文名称，例如深圳
        unit: 温度单位 c=摄氏度 f=华氏度
    """
    mock_data = {
        "city": city,
        "temp": "27℃",
        "condition": "多云",
        "humidity": "65%"
    }
    result = {
        "success": True,
        "data": mock_data,
        "msg": "天气查询成功"
    }
    return json.dumps(result, ensure_ascii=False, indent=2)
```

### MCP Client 侧配置（接入 Agent）
```json
// mcp_config.json
{
  "mcpServers": {
    "weather": {
      "command": "python",
      "args": ["mcp_server_weather.py"]
    }
  }
}
```

### MCP Tool 核心特性
- 启动 Server 后，MCP Client 会自动调用 `tools/list` 获取全部工具列表、描述、参数 Schema
- Client 调用 `tools/call` 传入参数，执行函数并返回结果
- 跨框架通用：LangGraph、Claude Code、Cursor 都能接入，不用单独写 Function Adapter
- 同样遵循原子原则：MCP Tool 只做原子动作，业务流程编排写在 SKILL.md

## Function Tool vs MCP Tool 对比

| 项目 | Function Tool（原生 Function Calling） | MCP Tool |
|------|---------------------------------------|----------|
| 运行形态 | 代码内嵌在 Agent 进程内 | 独立进程 MCP Server，进程间通信 JSON-RPC |
| 复用范围 | 绑定当前 Agent 框架（OpenAI/LangGraph） | 一次编写，所有支持 MCP 的 Agent 直接复用 |
| 发现机制 | 手动注册工具描述 | 自动工具发现 tools/list |
| 部署 | 同进程，简单 | 独立服务，可远程部署 |
| 适合场景 | 自研 Agent、快速原型 | 多 Agent 共享工具、生产环境插件化 |

## 开发规范（Tool 通用强制约束）

1. **单一职责**：一个 Tool 只做一件原子操作，禁止在 Tool 内部写多步骤业务逻辑（交给 Skill）
2. **入参强校验**，捕获异常，不要直接抛原始堆栈给 LLM
3. **返回标准化 JSON 结构**，统一 success 标识，方便 Skill 分支判断
4. **高危操作**（删除文件、写库）必须增加参数校验，由 Skill 层做人工确认
