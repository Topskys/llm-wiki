## 一、什么是向量 Embedding

Embedding（嵌入向量）：把非结构化数据（文本、图片、音频、视频）通过模型，转换成一段固定长度的浮点数数组，也就是向量。

核心思想：语义相近的内容，在向量空间里距离更近。

举个例子：
- 句子：苹果很好吃 → 模型输出向量 [0.12, -0.34, 0.56, ...]（比如 768 维、1536 维）
- 句子：水果苹果味道不错 → 向量和上面距离很近
- 句子：手机苹果性能很强 → 向量距离就远一些

向量本身没有可读含义，向量里每一个维度代表语义特征，模型学到的知识被编码进这些数字。检索时不是关键词匹配，而是计算向量之间的相似度（余弦相似度、欧氏距离等）。

一句话总结 Embedding：把内容翻译成向量空间里的坐标，方便计算机衡量语义相似度。

## 二、向量数据库 vs 传统数据库

传统数据库（MySQL、PostgreSQL、MongoDB）擅长精确匹配；向量数据库（Chroma、Milvus、Qdrant、Pinecone）擅长近似相似度检索。

| 对比项 | 传统数据库 | 向量数据库 |
|--------|-----------|-----------|
| 存储对象 | 结构化数据：数字、字符串、日期、JSON | 向量 Embedding + 元数据 |
| 查询方式 | 精确匹配：where name="xxx"、等值、范围查询 | 近似最近邻搜索 ANN：找向量空间里最相似的 TopK 向量 |
| 索引 | B 树、哈希索引、倒排索引 | HNSW、IVF、FAISS 等向量专用索引 |
| 核心能力 | 事务、关联查询、分页、聚合、强一致性 | 海量向量快速相似度检索，支持向量过滤 |
| 适用场景 | 业务订单、用户信息、日志，关键词搜索 | RAG 知识库、图文检索、推荐、人脸检索 |
| 短板 | 向量检索极慢，向量一多基本不可用 | 不擅长复杂事务、多表 join，不适合精确业务查询 |

### 关键细节
- **传统库也能存向量字段**：比如 PG 可以用 pgvector 插件存向量，但它本质是给关系型数据库增加向量能力，大规模千万 / 亿级向量检索性能弱于专业向量库。
- **ANN 近似检索的含义**：向量数据库不是 100% 找到全局最相似向量，是牺牲一点点召回精度，换取百万、亿级向量毫秒级查询。传统数据库是"找完全符合条件的数据"；向量数据库是"找看起来最像的几条"。
- **元数据**：向量库除向量外，还可以附带元数据（原文、ID、时间、标签），支持向量检索 + 元数据过滤，例如：找和问题向量最相似的文档，并且只筛选 2026 年发布的。

## 三、简单通俗总结

- Embedding 向量：文字 / 图片转成一串数字坐标，语义相似，坐标挨在一起。
- 传统数据库：像字典，按字精准查找；
- 向量数据库：像地图，找坐标附近最近的几个点，用来做语义搜索、RAG。

### 补充：RAG 里的完整链路
文档 → 切分 chunk → Embedding 模型转向量 → 存入向量库；用户提问 → 问题转向量 → 向量库检索 TopN 相似文档 → 把文档丢给 LLM 生成答案。

## 四、向量搜索为什么快（后续追问）

### 一句话核心
向量搜索不是遍历全部向量挨个算距离（暴力搜索），而是用专门的向量索引，在高维空间里做"剪枝"，只在一小部分候选向量里找最近邻，牺牲一点点召回率，换来毫秒级查询。

### 1. 先看暴力搜索（最慢）
假设库里有 1000 万条 768 维向量。暴力做法：拿到查询向量，和库里面每一条向量全部计算余弦距离，排序，取 TopK。计算量：1000 万次向量点积。缺点：向量越多，耗时线性上涨，千万级向量基本没法线上实时用。暴力搜索 = 挨个比对所有人，找出离你最近的几个人。

### 2. ANN 近似最近邻算法（向量数据库核心）
ANN（Approximate Nearest Neighbor），就是向量库加速的底层。主流索引：HNSW、IVF、FAISS Flat/IVF_PQ。

**① IVF（倒排文件索引）思路：先聚类，再局部搜索**
- 建索引阶段：把所有向量做聚类，分出很多"桶（聚类中心）"
- 查询时：先算出查询向量，找到离它最近的少数几个桶，只在这几个桶里面做距离计算，跳过绝大多数桶里的数据
- 举例：1000 万向量分成 1000 个桶；查询只找最近 3 个桶，只算 3 万条向量，而不是 1000 万条。
- 代价：如果最相似向量刚好分到别的桶，就会漏掉，召回率下降一点。

**② HNSW（层次化导航小世界，现在最常用）思路：多层跳表 + 图结构**
- HNSW 是 Milvus、Qdrant、Chroma 常用的索引。
- 建索引：构建多层有向图。高层是稀疏点（粗略导航），底层存储全部向量。
- 查询：从最高稀疏层快速跳到靠近目标向量的区域，逐层往下导航，不需要遍历全部点，沿着图的边"跳着搜索"，快速收敛到候选集。
- 类比：找一个城市里离你最近的咖啡店。暴力：全城每家店全部算一遍距离。HNSW：先看全省地图跳到这个城市，再看城市地图跳到你所在片区，只在附近几条街找。

**③ PQ 乘积量化：压缩向量，减少内存占用**
- 向量原始是 768 个 float（每个 float4 字节，单条 3072 字节）。PQ 把高维向量压缩成很短的编码，把向量从内存占用大户变小。
- 好处：更多向量可以放进内存，避免磁盘 IO（磁盘读取是巨大瓶颈）；距离计算也变成查表，速度更快。
- 代价：压缩会损失精度。

### 3. 传统数据库为什么做向量检索很慢？
传统数据库 B 树 / 哈希索引，是为精确等值、范围查询设计，不支持高维空间的近邻搜索。你在 PostgreSQL 里存向量字段，不用 pgvector 的向量索引：每次查询，依然是全表扫描，每条向量计算距离，本质就是暴力搜索，数据量大直接卡死。pgvector 可以开向量索引，但底层 ANN 实现相比专业向量库，在亿级向量场景优化弱一些。

### 4. 向量搜索快的几个关键总结
- ANN 剪枝：不扫全量，只搜索局部候选集（最大加速来源）
- 向量量化：压缩向量，省内存，减少 IO
- 内存优先：向量库尽量把索引和向量放内存，避免磁盘慢 IO
- 向量距离计算做硬件加速：SIMD 指令，批量浮点数运算

### 5. 权衡（非常重要）
**速度 ↔ 召回率 是 trade-off**。调大参数（多搜候选点）：召回更高，速度变慢；调小参数：速度更快，但有可能漏掉最相似的向量。

简单类比：暴力搜索 = 考场挨个检查全部 10 万份试卷，找和你答案最像的卷子。ANN 向量索引 = 先按答案特征分好班级，你只去最相似的 2 个班级里面找试卷，剩下 98 个班级直接跳过。
