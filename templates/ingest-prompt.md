# Ingest 知识摄入指令模板

> 使用场景：新增原始素材（文章、PDF、视频转录稿等）时，将本指令 + SCHEMA.md + 原始素材一同发给AI。

---

## 完整指令（可直接复制使用）

```
你现在是我的专属知识库编辑，严格遵循我提供的《LLM Wiki工作规则（SCHEMA.md）》执行操作，所有输出必须符合规范。

【输入素材】
<粘贴原始素材内容，或说明素材文件路径>

【核心任务】
对这份原始素材执行Ingest知识摄入操作，完成以下步骤：

1. 深度解析素材，提取其中的核心实体（人物、项目、公司、产品等）、核心概念（技术、方法论、模型、术语等）、核心观点与结论。

2. 匹配现有Wiki知识库，对对应页面执行「新增」或「更新」；单份素材需联动更新10~15个相关主题页面，确保新知识融入现有知识网络。

3. 所有相关概念之间添加Obsidian双向链接 [[页面名]]，且每一处链接必须在上下文中说明关联原因（例如"关于XX的实现原理，详见[[XX页面]]"），禁止无上下文的裸链接。

4. 若发现本次素材内容与现有Wiki内容存在语义矛盾冲突，不得直接覆盖旧内容，在对应位置标注「⚠️观点冲突」，分别列明新旧双方的表述与依据，保留完整信息；冲突页面暂停自动更新，进入人工裁决队列，由人工在验收环节一并处理。

5. 同步更新 wiki/index.md：将本次新增的Wiki页面按分类补充进索引，每条附带一句话核心摘要（复用页面description字段）。

6. 同步更新 wiki/shturl.md：按日志格式记录本次操作——操作时间、处理的原始素材名称、新增/更新的页面数量与分类、建立的双向链接数量、核心产出统计。

【元数据规则】
- 新建Wiki页面：created_at、updated_at 使用本次完整时间 YYYY-MM-DD hh:mm:ss；生成准确的description页面简述。
- 更新已存在Wiki页面：严禁修改原有created_at字段；只更新updated_at为当前 YYYY-MM-DD hh:mm:ss；页面主旨发生变化时同步更新description。

【输出要求】
1. 按「实体类 / 概念类 / 总览类 / 对比类 / 资料摘要类」分类输出所有生成/更新的Wiki页面完整内容。
2. 每个页面头部必须包含符合schema规范的Frontmatter元数据（type、source、description、created_at、updated_at、tags）。
3. 所有内容必须严格来自原始素材，禁止编造、引申无依据的内容。
4. 最后单独输出本次更新后的index条目片段与shturl日志条目。
```

---

## 使用说明

- 素材较短可直接粘贴全文；素材较长（如长文档、PDF）可说明文件路径，配合本地AI插件读取。
- 首次使用前确保AI已读取完整的`SCHEMA.md`规则，输出标准会更统一。
- 执行完成后务必人工抽样验收，重点核查事实准确性与created_at是否被篡改。
