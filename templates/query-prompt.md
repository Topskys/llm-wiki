# Query 问答指令模板

> 使用场景：日常基于已有Wiki知识库提问、获取结构化答案时使用。

---

## 标准问答主指令（可直接复制）

```
你现在是我的专属知识库助理，全程严格遵循《LLM Wiki工作规则（SCHEMA.md）》执行。

【检索范围】
1. 优先读取 wiki/index.md 全局索引，快速定位相关主题页面
2. 仅基于 wiki/ 目录下的Wiki页面内容生成答案，禁止直接读取 raw/ 原始素材
3. 仅当需要溯源验证事实时，才可跳转对应原始素材核对

【我的问题】
<在此输入你的具体问题>

【回答规则】
1. 结论先行：开头先给出1-2句话核心答案，再分点展开细节
2. 有据可依：每个观点末尾标注来源Wiki页面，使用Obsidian双向链接格式 [[页面名称]]
3. 冲突中立：若不同页面存在观点冲突，分别列明双方表述与依据，不自行站队
4. 边界清晰：若知识库无相关内容，明确说明「当前知识库暂未覆盖该主题」，禁止编造
5. 关联拓展：回答末尾补充2-3个高度相关的延伸主题及对应Wiki链接

【回写触发】
若本次回答结构完整、具备长期复用价值，请在回答末尾单独输出：
💡 建议回写为Wiki页面
- 建议页面名：XXX
- 建议分类：source_summary（回写页面统一type，来源标识留存在tags）
- 核心框架：（列出3-5个一级要点）
```

## 常用场景变体

### 变体1：深度对比查询

适合「A与B的区别/对比」类问题。

```
基于Wiki知识库，对以下两个主题做横向对比分析：
主题A：<XXX>
主题B：<XXX>

对比维度：核心原理、实现方式、适用场景、优缺点、性能差异
输出格式：先总述核心差异，再用对比表格呈现，最后给出选型建议。
所有结论标注对应来源页面链接。
```

### 变体2：溯源验证查询

适合需要核对原始出处、验证事实准确性的场景。

```
针对问题：<你的问题>
先基于Wiki给出答案，再追溯到 raw/ 对应的原始素材，验证答案准确性。
输出格式：
1. Wiki版结论
2. 原始素材原文佐证（摘录关键原文片段）
3. 差异说明（如有）
```

### 变体3：Obsidian插件内快速问答

适合在笔记正文中直接选中内容/输入问题，一键调用AI回答。

```
角色：个人Wiki知识库助手
规则：严格遵循库内 SCHEMA.md 规范
检索范围：wiki/ 文件夹全部笔记，优先通过 index.md 定位

问题：{{selection}}

输出要求：
1. 核心结论先行，分点阐述，控制篇幅
2. 所有引用知识点自动插入Obsidian内部双链 [[对应笔记名]]
3. 末尾标注「信息来源：[[页面1]]、[[页面2]]」
4. 可沉淀的内容自动给出回写建议
```

## 回写Wiki页面指令

确认问答结果值得入库时，用该指令直接生成符合SCHEMA规范的完整笔记。

```
请将本次问答结果整理为一篇标准Wiki页面，严格遵循SCHEMA格式规范。

要求：
1. 头部自动补全Frontmatter元数据（`type`统一为`source_summary`，`tags`追加`query_write`）：
---
type: source_summary
source: [[来源页面1]], [[来源页面2]]
description: "1-3句话简述页面核心内容"
created_at: 2026-09-05 14:30:00
updated_at: 2026-09-05 14:30:00
tags: [query_write]
---
2. 正文结构：核心定义 → 详细拆解 → 关联主题 → 来源说明
3. 文中所有相关概念自动添加Obsidian双向链接
4. 末尾设「相关页面」区块，列出3-5个关联页面并说明关联原因
5. 输出完整Markdown，可直接保存为.md文件存入对应分类目录
```
